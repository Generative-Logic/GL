# Core concept — Static memory (statification) `[DRAFT]`

## Complete canonical-class state

`LbMemory::canonicalEquivalenceClassesMap` stores complete scope-visible classes on the existing deloadable main arena. Its four cold-blob facets use tags 839–842. The prior normal/special representative map and independent canonical-change map use tags 843–846. Both container visitors and live-byte accounting include the new state; facts clones copy it, and scope wipes erase covered keys. No pool or capacity setting changes. See the [complete class view](05_equivalence_classes.md#complete-target-scope-class-view).

> Statification replaces per-LB heap containers with fixed-pool **blocks** and **pages**, addressed by stable **virtual page ids**. The current prover uses main, persistent, mail, logic-block-body, and GPU-host pools and completes measured FTA runs. Per-worker `ScratchArena` / `ScratchString` / sealed pages supply the separate transient substrate, released at their task boundaries. The compiled-definition layer remains an open statification item; see I-137.

> **Historical paged-refactor transition.** The initial scattered model allocated each element separately and indexed it by a virtual byte offset. The paged replacement packed elements inside fixed-size pages to address the measured cache-miss cost. [The paged model](#the-paged-model--current) describes the current substrate. Some detailed component sections retain historical descriptions; use the statification cookbooks and current source for implementation interfaces.

---

`logical_block/equality_propagation.hpp`, `applyEquivalenceClassToNegatedEquality`, bounds copied class blobs by a per-class scratch frame and the descendant sort index by a per-call frame. Recursive emissions allocate above the outer live view and rewind only their own temporary bytes; repeated scans no longer accumulate copies until worker-task release.

## The hierarchy

| Level | Size knob (`parameters.hpp`, compile-time) | Owner | Unit handed down |
|---|---|---|---|
| Pool | `static_pool_bytes` (default 6 GiB) | `GlobalMemoryManager` — one per pool | Block |
| Block | `static_block_bytes` (default 256 KiB, a power of two) | `LbArena` — one per LB | Page |
| Page | `static_page_bytes` (default 2 KiB, a power of two; [D-411](../40_decisions.md#d-411)) | the paged containers, via `LbArena`'s page tier | Elements (packed contiguously) |

Three levels: the page tier is **restored** (the bump-arena cutover had removed it). Each `LbArena` carves its `static_block_bytes` blocks into `static_page_bytes` pages (`allocPage` / `freePage`), and the paged containers pack their elements contiguously within a page — see [The paged model](#the-paged-model--current) below. Validated by `isValidStaticMemoryConfig` (pool a whole multiple of a power-of-two block) and `isValidStaticPageConfig` (block a whole multiple of a power-of-two page) ([`parameters.hpp`](../../../GL_Quick_VS/GL_Quick/src/parameters.hpp)), asserted in the `Prover` constructor. These three sizes are compile-time constants in `parameters.hpp`, identical for every batch and never read from a config ([D-139](../40_decisions.md#d-139)). See [`04_configs.md`](../04_configs.md) for the field reference. The four original pools comprise the main pool (6 GiB, [D-410](../40_decisions.md#d-410)) plus three extra reservations — persistent (1 GiB), mail (2 GiB), LB-body (2 GiB) — totaling a fixed 11 GiB program-start reservation. GPU use adds an independent, lazily initialized 4 GiB default reservation, for 15 GiB total address space; its separate budget can be overridden before initialization. The reservation is address space: each block is committed before its first grant, while returned blocks in the four original pools beyond a 64 MiB reuse reserve per pool are decommitted after phase 3 and recommitted at the same address when granted again. Current backing commitment is distinct from the carve and lifetime high-waters ([D-480](../40_decisions.md#d-480)).

## The paged model — current

The cold path is being moved from the scattered bump arena back to a **paged** model
(reviving the page tier the bump-arena cutover removed). The page tier, the paged
containers, the paged cold strings, and the **hot string arena** are implemented and
unit-verified. Cold strings are interned **within a single page** (no straddle), so
`view` is always contiguous — what had been the open straddle-read debugging item is
closed. The remaining steps are the byte-level-API retirement and the full-pipeline
determinism gate.

- **Page tier on `LbArena`.** The manager dispenses fixed-size `static_page_bytes` pages and nothing smaller: `allocPage` (bump a page up — reusing the per-LB free-list first), `freePage(vid)` (poison + park on the free-list; freeing the *tail* vid rolls the page cursor back, the LIFO page-level bump-back), `pageAt(vid)` (resolve a stable virtual id to its physical page). Pages are carved from the same `static_block_bytes` blocks (128 × 2 KiB per 256 KiB block with the current defaults), drawn mode-aware (cold / hot). Hot and cold share this one page substrate.
- **`PagedVector<T>`** ([`memory_infra/paged_vector.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/paged_vector.hpp)) replaces `ArenaVector<T>`: elements pack **contiguously within a page** (the cache fix), indexed `page = i >> shift, within = i & mask`. Its directory lives **in the arena, never the heap** — adaptive in five rungs: empty → a single inline data-page vid → one directory page of up to `dirCap = pageBytes/sizeof(int32)` vids → a **two-level directory** (an L2 root page of level-1 directory-page vids; each L1 page holds up to `dirCap` data-page vids, so the index itself spans several pages — capacity `dirCap²` data pages). The full single directory page becomes L1 page 0 with no copying; the page index splits into `(L1 index, slot)` by one shift + one mask (`dirCap` is a power of two), and `dataVidOf` resolves the deeper level with one extra `pageAt`. Beyond `dirCap²` data pages, an L3 root indexes L2 roots with the same L1 layout; vector promotion retains the previous L2 root as child zero without relocating payload. Shrink frees empty L1/L2 branches and demotes at the boundary. `PagedHashIndex` constructs and releases the same third-level shape on reset. Overflow beyond `dirCap³` pages still asserts; signed 32-bit element/slot bounds are independent, and size/page arithmetic uses widened intermediates. Smaller containers keep their original depth and allocation pattern ([D-419](../40_decisions.md#d-419)). On a logic block's persistent arena (`LbArena::enableSubPages`, set by `LbMemory`), a container whose content fits half a page takes one power-of-two **sub-page slot** instead of a whole page (64 to 1,024 bytes at the 2 KiB page; `LbArena::allocSubPage` / `freeSubPage`): it starts in the smallest slot that holds its first growth, moves to a larger slot as it grows, and moves to one whole data page past the largest slot, before any directory exists; `PagedHashIndex` places a small bucket array (the 64-slot minimum in 256 bytes) the same way. The slots of a size class are carved from ordinary live pages of the arena, so compaction and the raw image move and restore them as pages; a slot is its page's vid plus a 16-bit byte offset (`firstOffset_`, added to every slot address, zero in every other shape), and `shift_` / `mask_` describe the slot's power-of-two capacity. Free slots of a class form an intrusive LIFO threaded through the slots; compaction first returns every carved page without a live slot to the page tier (`releaseEmptySubPagePages`), so a discharge still frees every block; the raw eviction keeps the lists across the round trip (`releaseAllForRawImage`), while a canonical eviction or a teardown empties them with `releaseAll` ([D-464](../40_decisions.md#d-464)). Scratch and mail arenas stay page-only. `erase` shifts left across pages and frees emptied tail pages (demoting the directory shape as it shrinks); `appendSpanBytes` emits one `memcpy` per page run, **byte-identical** to `ArenaVector` — the directory shape is invisible to the deload stream, which walks logical elements — so the deload image is unchanged regardless of depth. Scratch statement vectors, shared-record slots and ordered statement references use this page-tier substrate. Each single→two-level promotion (in `PagedVector` and `PagedHashIndex`) is counted on `GlobalMemoryManager` (`recordTwoLevelPromotion` → `twoLevelPromotions` / `peakPagesHeld`, printed once per batch by `reportPageStats`) — observability only (Rule 16 / [I-44](../30_invariants.md#i-44)), never a prover input; a forced-small-`static_page_bytes` run reports a non-zero count, the proof of a real spill.
- **Paged cold strings.** `ColdStringTable`'s byte storage is a `PagedVector<char>` byte pool, and each string is interned **within a single page** — `appendRunNoStraddle` pads a page tail rather than let a string cross a boundary. So `view` **always** returns a contiguous `StrSpan` (the run-length check is the no-straddle guard, not a fast path with a fallback), and every `decodeView` consumer is safe with no page-aware rewrite. The padding makes the physical pool non-dense, so the deload streams the **logical** per-string bytes (lengths + `appendContentBytes`'s per-string walk), keeping the on-disk image dense and **byte-identical** to the pre-paging form — ids, dedup, and proof output unchanged. A string longer than one page would assert (a hard limit; expression / name text fits comfortably).
- **In-place background compaction.** `LbArena::compactPages` packs an LB's live pages onto the contiguous prefix of its blocks (vid-order permutation: backward chain-walk for paths + a single scratch page for cycles) and returns the emptied blocks to the pool. **Content-invisible**: containers hold stable vids and resolve through `pageAt`, so compaction rebinds only the vid→physical table — no container touch, no pointer-cache refresh, the `dirty` state untouched. `LbMemory::reshuffle` calls it, gated by `steward::arenaNeedsCompaction` (free pages parked inside held blocks at least one block and at least an eighth of the held span). The steward invokes it on idle logic blocks in the prefetch region, and every worker invokes `steward::compactIfFragmented` on its claimed logic block at the end of phases 1 and 3 (after phase-3 scope cleanup and shared-key collection, before the memory sample and claim release; [D-434](../40_decisions.md#d-434)), with a per-worker scratch on the LB-body pool ([D-420](../40_decisions.md#d-420)); this is the only block reclamation for a logic block that is never deloaded.
- **Scratch string arena + sealed pages on the byte-bump tier.** The scratch per-worker arena and the sealed-page handoff fill from the byte-bump tier (both COLD since; byte-bump since [D-189](../40_decisions.md#d-189)). `allocBytes(bytes)` is a resolved `alloc` — a byte-bump allocation that pads to the next block boundary rather than cross it, so a scratch allocation **never straddles a block** (must fit one). `mark` captures `(generation, cursor)`; `rewind` rolls the cursor back to the mark and poisons the reclaimed span (`popTo`), so the entire freed span reads loud garbage (the `ScratchString` tripwire); `reset` is `popTo(0)` + generation bump; `releaseAll` returns the blocks (the per-task scratch release). `SealedPageSet::freePages` is `reset` + `releaseAll`. The byte tier is independent of the page tier, so scratch fill never collides with the `allocPage` containers (`PagedVector` / `ColdHashSet`) — they can share one arena.
- **Remaining for page-only.** The byte-level `LbArena` API (`alloc`/`popTo`/byte cursor) still backs the `ArenaVector` cold containers; once those are paged too it can be retired and the manager is page-only. Debugging then follows: the full-pipeline determinism gate (`run_bumped_gate.log` vs the baseline).

> The detailed component sections below predate this refactor — they describe the scattered bump-arena model, the `ArenaVector` two-level offset spine, the per-string cold allocation, and the copying-compaction `reshuffle`. They are accurate for HEAD and are being rewritten to the paged model captured above.

Together these memory changes reduce identified GL-owned RAM at the matched FTA comparison state from 2301.24 MiB to 2096.92 MiB: 204.32 MiB (8.88 percent) saved. This includes directly owned retained capacity and is not a fresh peak measurement. The full proof output remains byte-identical.

## Derived hash bucket occupancy

`cold_hash_map.hpp`, `HashMap::rebuildIndex`, `mintAbsent`, and `indexInsert`, use a strictly below 75-percent occupancy limit. The minimum remains 64 slots and capacity remains a power of two. Rebuilds place stable key identifiers in derived buckets; ordinary and pre-probed insertions use the same boundary. Exact key comparison resolves every collision. Canonical key/value streams do not contain bucket placement. Fused posting storage retains its separate half-full bucket policy. Higher cold-map occupancy trades fewer bucket pages against longer probe chains.

## Prefix-packed origin strings

`BytesKeyStore::packPrefixes` optionally stores sorted-key suffixes and eight-byte predecessor/prefix rows while preserving local identifiers, full lengths and hashes. The initial integration binds `LbMemory::originStrings` only. Each group of sixteen sorted keys starts with a full key. Packing runs at the existing quiescent phase-1 and phase-3 worker seams, after at least 1024 keys and subsequently after population doubles. A temporary full-key copy and paged ordinal sort build a candidate; the format changes only if complete suffix and metadata pages are smaller. Temporary containers use the general worker scratch arena and return their pages at function return. The existing worker-exit release returns that arena backing before the barrier. Transient packing capacity remains part of the RAM budget while the worker is active.

`ValueInterner::copyView` and `decodeOriginKeyCopy` write decoded bytes into explicit caller-owned string scratch. Callers keep their scope alive across all dependent reads and mints. `compareKeys` and `mailIdCompare` compare borrowed suffix segments synchronously without a decode cache. The old contiguous `decodeAt` door asserts for a packed store; it cannot return a dangling reconstructed view. Heap export boundaries use their existing owning string results.

Canonical lengths and bytes remain in original identifier order and reconstruct the full strings; copying a table does the same. Canonical release clears prefix metadata through the table's existing release door, without new tags. Raw images preserve metadata and suffixes together. The owner descriptor lives beside the table and is declared before it. Tables using this optional format are append-only until wholesale clear; other key-store formats retain stable erase and compaction. Named resident accounting includes prefix metadata once. No proof or provenance decision reads compression metadata.

The earlier compaction-scratch implementation retained freed packing capacity. General worker scratch now bounds that capacity to the worker lifetime. Combined memory savings require a matched-state capture because fused-edge storage, bucket occupancy and string packing can overlap. The full string-family model remains unimplemented.

## Shared native hash-key payload

`cold_hash_map.hpp`, `SharedBytePool`, owns one immutable byte dictionary per `LbMemory`. The four `HashMemory` instances bind their normalized whole/subkey and encoded-map keys, remaining-argument and owner keys, forward normalized-key value blobs and reverse-index keys to it. Maps retain separate local identifiers, hash indexes, memberships, run order and owner records. Sharing byte identity never shares logical facts between tables or logic blocks.

`BytesKeyStore` keeps local length/hash metadata with private shared-payload identifiers. The shared mode of `BlobCsrValueStore` keeps canonical offset columns and four-byte payload references. Normalized-key values remain page-contained; rule and owner stores also support private paged records above one shared page. `poolByteCount` and all existing deload facets still describe and emit canonical bytes. Projection readers receive the original bytes. Existing canonical tags, row order and byte streams therefore remain unchanged.

The dictionary and client registrations live with the block. `SharedBytePool::collect` runs under the exclusive worker claim after phase 1 and phase 3 have finished using borrowed views: mark client references, erase unreferenced dictionary entries in stable order, remap private payload identifiers, and move retained no-straddle bytes forward before releasing unused pages. It uses the existing separate compaction scratch arena. Dictionary mutations mark the owning block dirty so a raw image cannot silently retain stale metadata. The arena's ordinary page compaction subsequently returns empty whole blocks.

Emptying the final key/value client releases the dictionary immediately, including grid cleanup that has no later worker collection. Canonical release clears all map clients and derived reverse indexes before releasing the shared dictionary. Canonical reload reconstructs sharing from unchanged per-map byte streams. Raw eviction preserves the dictionary pages and metadata together with the clients; payload is still addressed through arena offsets rather than physical pointers. The memory census counts shared payload and locations once in `sharedNativeKeys`, and counts value identifiers at their owning value pool, independently of canonical serialized sizes. See [I-275](../30_invariants.md#i-275).

On the measured full F3 workload (2026-09-28), two sequential runs preserved all theorem and proof files while peak native working set fell from 8,569.5–8,576.7 to 7,051.4–7,055.0 MiB. The peak batch changed from IncubatorGauss1 to IncubatorPeano1. Largest main-pool peak fell to 4,212.50–4,212.75 MiB of the unchanged 6,144 MiB reservation. FTA working set showed no material saving. The measured `Memory` shell is 255,336 bytes, 5,120 bytes larger, and still occupies one 256 KiB LB-body slot.

## Batch byte dictionary — key bytes shared across logic blocks

The per-block dictionary above shares bytes inside one block. Across blocks the same bytes recur: at the IncubatorPeano1 peak the 14 duplicated byte families held 698.1 MiB of pool pages with 7.5 MiB of distinct payload, because every block installs the same mailed rules and mints the same names in the same order ([D-490](../40_decisions.md#d-490)).

`cold_hash_map.hpp`, `BatchByteDictionary`, is one process-wide, never-deloaded string table on the LB-body pool (`memory.cpp`, `batchByteDictionary`, the `skeletonInterner` precedent). A `BytesKeyStore` location with a negative `byteStart` refers to the dictionary entry whose first byte sits at position `-byteStart - 1` of the dictionary's byte pool; the row keeps the key length, so a read is one page resolve with no entry-table read (`BatchByteDictionary::referenceOf`, `bytesAt`). Every read path resolves it (decode, hash, equality, prefix walk, copy, canonical stream). Participating stores (`LbMemory::forEachBatchSharedStore`): the seven per-block string tables and the payload store of `sharedNativeKeys`, whose clients keep their block-local pool identifiers.

- **Mint-time lookup.** A participating store looks a new key up in the active dictionary (`BytesKeyStore::appendKey`, `bulkLoadKeys`) and stores a reference on a hit. Without an active dictionary it stores the bytes, so contexts that never share are unchanged.
- **Nominate.** At each block's end-of-phase-3 seam (`LbMemory::shareBatchBytesAfterPhase3`, after `SharedBytePool::collect`), rows minted since the store's scan mark that the dictionary misses are nominated into `batchByteCandidates`: `kBatchByteCandidateStripes` mutex-guarded stripes, each keeping one copy per distinct payload with a count. Each row is hashed once; the digest serves the dictionary probe, the stripe choice and the stripe's insert (`HashMap::mintHashed`). The stripe comes from digest bits 32 and up, which neither a stripe's bucket index (low bits) nor the location tag (top 18 bits) uses; choosing it by the low bits would start every probe of a stripe in 1/32 of its buckets.
- **Fill.** `ProofBarrier::finish` calls `BatchByteDictionary::promoteNominations` right after `steward->quiesce`, before the discharge wake: the only window in which no worker and no steward executor reads the dictionary. Payloads nominated at least twice become entries. The barrier logs `[BATCH-BYTES] nominated nominations added entries entry_bytes seconds` (distinct payloads, nominations including repeats) to `run_diagnostics.log`; the two sharing seams are the RT sections `PH3_BATCH_BYTES_SCAN_NEW` and `PH1_BATCH_BYTES_CONVERT_PENDING`, each with a nested `BATCH_BYTES_COMPACT`, so the RT report files them under their phases. Between barriers the dictionary is read-only.
- **Convert.** At the end-of-phase-1 seam (`LbMemory::shareBatchBytesAfterPhase1`) the rows nominated before the barrier that now hit become references; the end-of-phase-3 seam converts newer hits directly. Converted rows' bytes are reclaimed at once (`BytesKeyStore::compactAfterBatchConversion`: slide for a plain pool, `repackPrefixes` for the prefix-packed origin table, which never packs reference rows).
- **Scan marks.** Each participating store keeps two row marks (scanned, pending); `HashMap::eraseIf` reports removed rows (`beginStableErase` / `noteStableErase` / `endStableErase`) so the marks follow stable erasure exactly; `clear` and `release` reset them.
- **Lifetime.** Entries are never removed or moved while the process runs (each batch is one process), so references stay valid in raw eviction images and across clones (`copyKeysFrom` copies a reference). Canonical images stream logical bytes, so deload files are unchanged; a canonical reload looks its keys up again.

Conversion writes locations through `setAt`, so the block becomes `Restructured` and the next raw eviction rewrites its image. The dictionary is reported as `batchByteDictionary` and the nomination stripes as `batchByteCandidates` in the peak snapshot. Measured on the full pipeline: process peak 4,066 → 3,715 MiB (−8.7 %), every batch lower, output identical; prover time +2.9 %. See [I-301](../30_invariants.md#i-301).

## Fused dependency edge storage

`fused_posting_storage.hpp`, `FusedPostingStorage`, keeps endpoint keys, 64-bit values and signed link/revision words in separate packed page columns. Derived buckets point directly to stable edge slots. Backward-shift hash deletion moves only bucket references; removed edge slots enter a free list and never relocate surviving linked records. Scalar postings occupy 24 payload bytes per retained slot and domain-separated postings 32, before page rounding and directories. Hash occupancy remains the reference 50-percent policy. Canonical dependencies no longer use this storage: see *Shared canonical dependency edges* below.

`OrPostingIndex` preserves its one-direction posting order. Empty-head maintenance is amortized after at least 64 retirements and at least as many retirements as live edges. All-dead stores release every column. Canonical teardown clears these derived stores and canonical reload reconstructs them from unchanged source facts. Raw snapshots retain their columns, buckets and free-list state together. The resident census visits every owned column once through the existing index owner. No origin, scope, inference, deload tag or canonical byte format changes.

The independent FTA trial measured 101.25 MiB less identified GL-owned RAM (4.40 percent) and an 18.73-percent OR-view refresh self-time increase. It did not pass the original strict runtime gate; its later inclusion in the combined memory branch is explicitly maintainer-directed. Pool reservations, proof output and canonical formats remain unchanged.

## OR source storage

`memory_infra/or_implications.hpp` / `OrImplications` is one deloadable member of `LbMemory`, exposed by a reference alias on `Memory`. Its eight facets occupy tags 829–836: source keys and records, ordered leaf/complement pairs, source levels, pending source/fact/class events, and queued retirements. Canonical and raw deload preserve all this logical state. Fact-template clones copy it; the union scope wipe retires exactly the sources and events in the closed scopes; discharge and counterexample teardown clear it. Original source validity remains separate from the effective scopes used by matching.

`memory_infra/or_implication_postings.hpp` / `OrImplicationPostings` supplies the derived mutable index primitive: exact key/value lookup, doubly linked live postings, immediate unlinking, recyclable edge slots, and batched empty-head maintenance. It is not part of the canonical source image. Positive OR consumption registers sources after known/levels admission; the evaluator emits only selected internal-mail heads and history. See [I-247](../30_invariants.md#i-247).

`memory_infra/or_implication_match_index.hpp` / `OrImplicationMatchIndex` groups derived lookup views by owner, canonical entry, signed template, effective scope, and substitution token through one domain-separated `OrPostingIndex`. An entry belongs to one canonical form and effective scope and is keyed by them ([D-547](../40_decisions.md#d-547)): every spelling with that form shares it, source-leaf and known-fact views alike, and the known-fact views are its carriers, posted once under the entry's template. `logical_block/or_implication_processor.cpp` / `OrImplicationProcessor::ensureOrCanonicalCache` finds a spelling's entry with one text-only canonicalization (`canonicalOrFormId`); `bindOrCanonicalView` and `refreshOrCanonicalViews` never insert known facts or register GPU premise usage. An entry posts the tokens of its canonical form, and each view posts only the tokens its own spelling adds to that form (`postOrViewTokens`), so a class change on any member that rewrites a spelling reaches its entry. Whole substitution tokens use `forEachSubstitutionToken`, not substring matches.

The matching index owns all entry and posting mutations. `postings` and `caches` expose read-only tables; `publishCache`, `settleCache`, `moveView`, `retireCache`, `addViewTokens`, `eraseViewTokens`, `markTokenUsersDirty`, `eraseView`, `eraseFact` and `retireSource` maintain complete forward/reverse relationships. `publishOrCanonicalCache` streams the canonical form's tokens directly into the publication operation, preserving mint order without an extra token collection. An entry's form never changes in place: a moved form moves the entry's views to the entry of the new form. Fact and leaf identities use named constructors; source evaluation has its own `OrEvaluation` key and cannot be mistaken for a lookup view.

Known-row writes that do not already use `stageWatchArrival` pair their OR notifications through `publishKnownStatementKey` / `eraseKnownStatementKey`. The caller still owns levels and ordinary negation-watch cleanup. This preserves the original event positions; the ordinary watch-arrival door continues to stage its own OR notification, and scope wipes keep their single derived-index invalidation.

The initial class-scope directory is built once. A class refresh (`EquivalenceProcessor::refreshCanonicalClasses`) dirties an entry (`OrImplicationMatchIndex::markTokenUsersDirty`) only when the normal representative of a token of its canonical form, or of a token one of its spellings adds, moved at the entry's scope (change bit 1, which also covers a member new at that scope) or the locality of that token's rewrite equality changed (change bit 16, recorded per member by `rebuildCanonicalScope`); a class change with neither, such as a larger member joining or new history lines or levels, leaves the entry current ([D-498](../40_decisions.md#d-498)). A dirty entry canonicalizes its own canonical text once: an unchanged form settles in place and queues its users for matching again; a moved form moves every user to the entry of the new form, merging with a live one, and its sources rebind their leaves. Descendant equalities queue separate descendant views: a class below an entry on a token of its canonical form projects all its users, on a token a spelling adds only that spelling's view. Refresh work is deduplicated and sorted by decoded identities using paged ordinal sorting. Last-user removal immediately unlinks token and scope postings before batched dead-entry cleanup. The standard-processing drain reconciles this work before invoking the source evaluator. Own-scope retirement releases all source postings while preserving any independently used fact views.

`LbMemory::orImplicationMatches` owns this derived index on the same arena as the source store, and `LbMemory::liveBytes` includes every cache, posting, view and pending-work column. It has no canonical deload facets: canonical release clears it while the arena is resident, and clones/canonical reloads start empty for reconstruction from source state. Raw eviction preserves its pages and object descriptors together. Discharge and counterexample teardown clear it. A union scope wipe invalidates the derived index once, retaining canonical ancestor sources for the next reconstruction; no per-class or per-arrival global invalidation is used.

OR intent follows `logical_block/disintegration_processor.cpp` / `CollectedArena` through `disintegrateExpr2` / `addToFinal` into `DisintProducts::orSources`. The final statement walk passes that intent to `addStatement`, which activates `logical_block/or_implication_processor.hpp` / `registerOrImplicationSource` only after successful known/levels registration and canonicalization, including nonlocal statements absent from the local output vector. Collection and rejected products cannot activate sources. Ground leaves reuse `flattenRegistryOrLeavesScratch`. Known-row writers/removers stage relevant signed-core changes through `stageOrFactChange`; class merges queue members only once the derived index is built, since a fresh index will read current classes. The evaluator replaces eager per-source K/subset instantiation; the compiled exclusion family remains on LogicalEntity for selected-firing reconstruction and ordinary proof history.

`logical_block/or_implication_processor.hpp` / `prepareOrImplicationMatches` builds all pending source views before one known-registry scan for the batch's newly watched signed cores. Existing-core events use exact queued keys. It settles canonical changes, then joins complementary template buckets only across comparable lookup scopes, once per changed source view and once per changed entry fact role, and queues source/scope evaluations. `retireOrImplicationSource` unlinks every source-leaf view, preserves independent fact views sharing the same owner, and removes fact indexes for a core after its last source leaves. No rewrite locality is stored: for ordinary firing ownership `selectOrImplication` computes, for each spelling it considers, whether the equalities rewriting it into its entry's form are local (`rewriteLocalAt`), from the current classes. The evaluator consumes this prepared work; no source/fact equality chooser is duplicated.

OR leaf keys are derived by `bindOrSourceViews` from the canonicalized **whole OR**, using `flattenRegistryOrLeavesScratch`. This is required for equality leaves: the existing scalar fact canonicalizer deliberately leaves standalone equalities unchanged, while an OR's argument rewrite also changes its equality disjuncts. The entry of the OR's canonical form at the lookup scope serves all its ordered leaf views; each view stores its own complementary canonical id and template id. A known OR fact with the same canonical form shares that entry while retaining its whole-expression template. `ensureOrCanonicalCache` owns the common chooser and token work; refresh re-flattens affected sources once per owner/scope after their entry moved.

## Existence replay lookups

`memory_infra/existence_lookup_indexes.hpp` / `ExistenceLookupIndexes` owns six derived lookup structures on the block arena: three normalized demand indexes, receipt keys grouped by scope, and algebra/integration source-to-park postings. Demand and receipt key lookups extend on append and rebuild after erasure/reset. Source postings are built once from records, then maintained at source insert, equality replacement and retirement. All lookup outputs are ordered and checked through the existing proof paths.

The caches have no canonical deload facets. Canonical release clears them before returning pages; clones and canonical reloads start unbuilt; raw eviction retains their pages and descriptors. Scope wipe, discharge, counterexample teardown and grid reset clear them. Their storage participates in `LbMemory::liveBytes`; the separately reported canonical source-container peak excludes these replay caches.

## GlobalMemoryManager

`GlobalMemoryManager::init` reserves virtual address space through `reserveAddressSpace`; `grantLocked` commits each first-carved block through `commitAddressSpace`, and destruction calls `releaseAddressSpace`. The operating-system reservation preserves the physical page alignment required by CUDA registered transfers. Pool sizes, virtual offsets and canonical deload bytes do not depend on physical base addresses.

[`memory_infra/global_memory_manager.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/global_memory_manager.hpp) / `.cpp`. One reservation at `init` (never freed during the run, never grown — the software model of the ASIC's fixed SRAM), made as address space by `reserveAddressSpace` ([`memory_infra/address_space.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/address_space.hpp)); `grantLocked` commits a block with `commitAddressSpace` when it is first carved; `acquireBlock` / `releaseBlock` under an internal mutex (LBs are processed in parallel and request blocks mid-sweep). Recycled blocks are re-granted before fresh ones, so the carve cursor doubles as a high-water mark of simultaneous demand; `blocksInUse` / `peakBlocksInUse` expose sizing telemetry. Pool exhaustion is an **assert naming `static_pool_bytes`** — never a fallback heap allocation ([I-95](../30_invariants.md#i-95), successor of the retired [I-13](../30_invariants.md#i-13)).

At `run_modes.cpp::fullRun` teardown, one `[pool-memory]` line reports the lifetime peak blocks, block size, exact peak bytes, and configured capacity for `staticMemory`, `persistentMemory`, `mailMemory`, and `lbMemory`. One executable invocation processes one batch, so each manager's lifetime high-water is that batch's physical peak. The four peaks stay separate because they need not occur at the same instant. `main.py --run-descriptor <postfix>` creates the paired . Its mail attribution table now contains the `MailLog`, global mail interner, and simultaneous `mailIn` peaks on the mail pool, plus the exact logical live-byte peak of deloadable `mailOut` on the main pool. Physical `mailOut` blocks are shared with each LB arena and therefore remain part of the main-pool physical high-water, not a fictitious separately summable component.

**Mid-burst admission throttle — REMOVED** ([D-148](../40_decisions.md#d-148), deleted). A mid-burst total-pool-usage throttle (a gate driving the steward's force-deload) once relaxed [I-106](../30_invariants.md#i-106). It was retired by the working-set pager ([D-161](../40_decisions.md#d-161) / [I-115](../30_invariants.md#i-115)) and its code (`throttled_` / `waitWhileThrottled` / the `kThrottle*` band / `burstClaim`) deleted with the HOT campaign. The retired throttle is distinct from the current residency pager and grant-pressure valve, which do read physical pressure. See the contract reconciliation note under I-106; proof state remains independent of residency timing.

**Determinism contract.** Grant order under the mutex is nondeterministic, which is sound only because no observable behavior may depend on physical block identity or grant order: containers address storage through per-LB **virtual offsets** (resolved to a physical address only at the access site), and the deloaded byte stream is a pure function of logical content. This is the load-bearing invariant of the whole design ([I-107](../30_invariants.md#i-107)).

**Process-wide instance.** `staticMemory` (function-local static) + `initStaticMemory(cfg)` — idempotent for an identical config, assert on a mismatching re-init (run modes may construct several `Prover`s per process; the sizing triple is a compile-time constant in `parameters.hpp`, so it is identical across them). Unit tests build private `GlobalMemoryManager` instances with tiny pools instead of touching the singleton.

## The persistent pool — the second reservation for `intToBeProved`

[`global_memory_manager.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/global_memory_manager.hpp) `persistentMemory` / `initPersistentMemory(cfg)`. A SECOND `GlobalMemoryManager` instance — its own reservation (`static_persistent_pool_bytes`, default 1 GiB), smaller blocks (`static_persistent_block_bytes`, default 32 KiB = 16 pages at the 2 KiB default), its own telemetry, and its own exhaustion assert (naming `static_persistent_pool_bytes`, selected by `StaticMemoryConfig::kind == PoolKind::Persistent`). It is one of the three sanctioned extra reservations under [I-95](../30_invariants.md#i-95) (the mail and LB-body pools below are the others); it never depletes the main pool.

**Why it exists.** The goal registry `Memory::intToBeProved` rides a per-LB `Memory::persistentArena` drawn from this pool — NOT the deloadable `lbMemory` arena — so it is **never deloaded** and stays resident for the LB's whole active life. The deactivation survey (`deactivateRecursively` / `deactivateUnnecessary`) reads `intToBeProved` for main-scope goals to decide `isActive`; on the deloadable arena the cold accessors assert residency, so the survey was residency-gated and SKIPPED on a deloaded LB — and which LBs are deloaded is timing-dependent (the hard-bound mass deload), so the deactivation decision, and the theorem set, were non-deterministic. With the registry persistent the survey reads it regardless of the main-arena state and gates on `isActive` ([I-108](../30_invariants.md#i-108), [D-149](../40_decisions.md#d-149)).

**Lifecycle.** Lazy (zero blocks until the first goal insert); in NO deload stream (`LbMemory::visitContainers` does not enumerate it, tags 35-37 retired), so a deload/reload of the main arena leaves it untouched; reclaimed exactly at discharge — `Memory::dischargeStatementContent` does `intToBeProved.resetToFresh` then `persistentArena.releaseAll` (resetToFresh frees the pages into the arena before the arena returns its blocks). Declaration order in `Memory` is load-bearing: `persistentArena` is declared before `intToBeProved` so the map destructs before its arena. Sized by peak simultaneously-active-LB count (each active LB pins ≥1 persistent block for its whole active life), not by content; the loud exhaustion assert is the backstop for an undersized pool.

## The mail pool — the third reservation for the cross-LB mail log

[`global_memory_manager.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/global_memory_manager.hpp) `mailMemory` / `initMailMemory(cfg)`. A THIRD `GlobalMemoryManager` instance — its own reservation (`static_mail_pool_bytes`, default 2 GiB), main-pool-sized blocks (`static_mail_block_bytes`, default 256 KiB; mail content is bulky, so large blocks keep grant traffic low), shared page size, its own telemetry, and its own exhaustion assert (naming `static_mail_pool_bytes`, selected by `StaticMemoryConfig::kind == PoolKind::Mail`). It is the second of the three sanctioned extra reservations under [I-95](../30_invariants.md#i-95) (the LB-body pool below is the third).

**Why it exists.** The pull-model `MailLog` stores every committed batch once and tracks per-(recipient, ancestor) cursors. The mail pool backs the `MailLog`, the global interner, and per-LB `mailIn` arenas only. `mailOut` no longer consumes it: each outgoing mailbox and its private interner occupy the owning LB's deloadable main-pool arena. Therefore `mailArena.blocksHeld` remains the exact MailLog physical high-water and `mailMemory.peakBlocksInUse` is the whole always-on mail total. The main-pool high-water includes outgoing staging, while `peakDeloadableMailOutBytes` reports its exact logical component peak without pretending the shared arena has exclusive blocks.

## The LB-body pool — the fourth reservation for the `Memory` node shells

[`global_memory_manager.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/global_memory_manager.hpp) `lbMemory` / `initLbMemory(cfg)`. A FOURTH `GlobalMemoryManager` instance — its own reservation (`static_lb_pool_bytes`, default 2 GiB), main-pool-sized blocks (`static_lb_block_bytes`, default 256 KiB), shared page size, its own telemetry, and its own exhaustion assert (naming `static_lb_pool_bytes`, selected by `StaticMemoryConfig::kind == PoolKind::Lb`). The third sanctioned extra reservation alongside the persistent and mail pools under [I-95](../30_invariants.md#i-95).

**Why it exists.** The last large per-LB heap user is the `Memory` node OBJECT itself (historically `new Memory` per LB). It moves onto this pool via the `LbStore` ([`memory_infra/lb_store.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/lb_store.hpp) / `.cpp`), an `Prover`-owned non-relocating slab allocator: it draws blocks and carves each into `sizeof(Memory)`-sized, `alignof(Memory)`-aligned SLOTS, placement-newing one `Memory` per slot. `create<Memory>` / `destroy` replace `new` / `delete`; `allocateSlot` / `freeSlot` are mutex-guarded (the CE-clone path allocates on worker threads). A slab is the only fit: `Memory` is non-copyable and non-movable (reference members, two `std::atomic` claim words, six embedded `LbArena`s), and the whole prover assumes pointer-stable LBs — so a slot is constructed once and NEVER relocated, and every raw `Memory*` (`parentMemory`, `simpleMap` values, the `mailLog` keys) stays valid for the object's life. The links stay raw pointers, not handles ([I-109](../30_invariants.md#i-109), [D-150](../40_decisions.md#d-150)).

**Shell room holds the page table.** A `Memory` shell fills one slot of a 256 KiB LB-pool block; the unused room holds the direct storage of its main arena's page table and carved-block list (`LbMemory::pageTableDirect_` / `pageBlockDirect_`, 12 288 + 512 entries), so a logic block's arena spills a directory block only past those capacities ([D-421](../40_decisions.md#d-421)).

**Lifecycle.** Lazy (zero blocks until the first LB is created); the free-list is intrusive (a freed slot stores the next-free link in its own raw bytes); within a store's life a freed slot is reused in place (across batches too) and no block returns to the pool mid-run, so the pool sizes to the peak simultaneously-live LB count, not churn. At teardown `releaseAll` (in `~LbStore`, mirroring `LbArena::~LbArena`) returns every block, so the several `Prover`s a process builds reuse the pool rather than summing their peaks — the only heap the store keeps is the block list (`blocks_`, one `char*` per block, the acknowledged tier-1 bookkeeping). Never enumerated for deload — the shells are the always-resident LB directory (their bulky content round-trips to SSD via the per-LB arenas), so the store plays no role in any deload / throttle / steward decision (the `intToBeProved` / mail-log precedent). The campaign moves the shells in stages: the pool + store landed first (scaffolding), then the allocation cutover (`new`/`delete` → `LbStore` at every grid / compressor / CE-filter / `cloneFactsTemplate` / `destroyGrid` site); the resident skeleton (`exprKey` and the `simpleMap` edges now off the heap, deload bookkeeping still to come) and the `LbArena` block-list bookkeeping follow, ending with zero transitive malloc per LB.

## The skeleton interner — the LB identity strings off the heap

[`memory.cpp`](../../../GL_Quick_VS/GL_Quick/src/memory.cpp) `skeletonInterner`. The LB's identity strings — `exprKey` (Batch 2) and the `simpleMap` routing keys (the [SimpleMapStore](#the-simplemapstore--the-lb-tree-routing-edges-off-the-heap) below) — move off the per-LB heap into ONE process-wide `ColdStringTable` (`= ColdHashSet<BytesKeyStore>`) on a function-local-static `LbArena{ &lbMemory }`. It is shared (deduped across all LBs) and never deloaded, so it stays readable while an LB's main arena is cold and after the LB is discharged — exactly where the per-LB `lbMemory` arena (deloadable) and `persistentArena` (discharge-reclaimed) cannot serve, and far cheaper than a per-LB never-deloaded arena (which would pin a 256 KiB block per LB for a handful of identity strings). `Memory::exprKey` is now a 4-byte `int32_t exprKeyId` (0 = empty / root sentinel) with an `exprKey` decode accessor — byte-identical to the former `std::string` member — plus `setExprKey`; the ids are never observable (decoded at every print / compare / chain / sacred-dump site, and sort comparators compare the decoded string), so the mint order is invisible to every artifact ([I-97](../30_invariants.md#i-97), [D-151](../40_decisions.md#d-151)). `deloadFiles` / `deloadChain` / `deloadedCounts` / `dischargedRegistryKeys` (tier-1 bookkeeping / per-LB POD) and the transient staging vectors stay on the heap for now (Batch 3).

## The SimpleMapStore — the LB-tree routing edges off the heap

[`simple_map_store.hpp`](../../../GL_Quick_VS/GL_Quick/src/simple_map_store.hpp) (at `src/`, beside [`mail_log.hpp`](../../../GL_Quick_VS/GL_Quick/src/mail_log.hpp), NOT under `memory_infra/`). The LB tree's DOWN-edges — historically the per-`Memory` heap member `std::map<std::string, Memory*> simpleMap` (parent → child by routing-key string; `parentMemory` is the inverse up-edge) — move off the heap into `SimpleMapStore`, the last large per-LB heap user on the otherwise-static `Memory` shell. The member is removed; `Memory` carries no map.

**Shape — the MailLog per-parent chain.** `SimpleMapStore` mirrors [`MailLog`](03_mail_system.md): an `Prover`-owned subsystem on a never-deloaded `LbArena{ &lbMemory }` (the LB-body pool the skeleton interner already uses — NO new pool), holding two cold containers that grow each parent's edges INDEPENDENTLY through one shared append-only pool, so an insert is O(1) and never shifts another parent's bytes:

- **`edges`** — `PagedVector<EdgeNode>` where `EdgeNode { Memory* child; int32_t keyId; int32_t prev; }`, APPEND-ONLY; each parent's edges form a newest-first back-linked chain via `prev` (the `mailRefs` pattern).
- **`heads`** — `TypedColdMap<int64_t, EdgeHead>` where `EdgeHead { int32_t lastEdge; int32_t count; }`, keyed by `lbKey(parent)` → its chain head (the `mailHeads` pattern).

**Keys and values.** The routing-key STRING interns into the shared `skeletonInterner` (a 4-byte `keyId`, deduped with `exprKey`'s strings — a DISTINCT id slot, since the routing key may differ from the child's `exprKey` at the recursion-block-#2 site, Rule 12). The parent IDENTITY is `lbKey(parent)` — the `uintptr_t` of its `const Memory*`, NEVER dereferenced (Rule 12, the `MailLog` convention). The child VALUE is a raw `Memory*` the prover DOES dereference (an address-stable `LbStore` slot, [I-109](../30_invariants.md#i-109)) — the one deliberate departure from `MailLog`'s identity-only keys, sound because the slab never relocates a slot and the store is cleared before any child is freed.

**API.** `linkChild(parent, key, child)` interns the key, appends one `EdgeNode`, bumps the head — single-threaded (LB birth, the `setExprKey` threading). `findChild(parent, key) -> Memory*` resolves the key with the non-minting `skeletonInterner.lookup` (burst-safe; an unminted key is id 0 = absent), then scans the parent's chain — the per-parent fanout is single digits, so the scan beats the old `std::map` string compares; a `nullptr` return is a defined "absent" result (the `find == end` twin), not a defensive fallback. `forEachChild(parent, fn)` collects the chain and SORTS it by the DECODED routing-key string (`compareSpans` over `skeletonInterner.view`, allocation-free), reproducing the old `std::map<std::string, Memory*>` iteration order byte-for-byte — so no enumeration-order-sensitive artifact changes. `clear` wholesale-empties; `empty` reports it.

**Never deloaded; two instances.** Like `MailLog`, the containers are pure runtime containers — never enumerated by `LbMemory::visitContainers`, so no `ContainerTag`, no deload image, no `dirty` (the `intToBeProved` / `MailLog` precedent); the store is absent from the sacred hashburst dump (no Rule-14 impact). Because the store is never deloaded, pointer-valued keys and grant-order layout carry NO canonical-bytes obligation — proof output stays content-deterministic via the logical edge content plus the `forEachChild` decoded-key sort. `Prover` owns TWO instances (`simple_map_store.hpp`): `simpleMapStore` (the main proof tree, `this->body`) and `ceSimpleMapStore` (the CE-filter tree, `ceBody`) — the two trees can coexist, so each is cleared at its own teardown (`destroyGrid` for the main store; `filterConjecturesWithCE` for the CE store). Sites route by phase: the `filter.cpp` main-path and `proof/proof_reconstructor.cpp` use the main store; `filter.cpp` uses the CE store ([I-110](../30_invariants.md#i-110), [D-152](../40_decisions.md#d-152)). Unit-tested in [`test_simple_map_store.cpp`](../../../GL_Quick_VS/GL_Quick/src/tests/test_simple_map_store.cpp).

## LbArena — the shared bump-arena substrate (cold + hot)

[`memory_infra/lb_arena.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/lb_arena.hpp) / `.cpp`. The same arena code backs the per-LB store, per-worker scratch and large sealed allocations. Small sealed allocations instead lease exclusive slices directly from main-pool blocks through `GlobalMemoryManager::acquireSealedSlice`. All these allocations use the ordinary pool grant path. The per-LB arena draws `static_block_bytes` blocks straight from the `GlobalMemoryManager` (the LB-side grant path, `acquireBlock`) and lays every cold container's bytes into ONE virtually-contiguous space: block 0 occupies virtual `[0, blockBytes)`, block 1 `[blockBytes, 2·blockBytes)`, and so on. In standard terms it is a region / bump allocator addressed by offset pointers, with copying compaction. The scratch string arenas are the SAME class, bound cold — `ScratchArena` is `using ScratchArena = LbArena` (see the Scratch string arenas section) — differing only in lifetime (deload-registered per-LB vs released per worker task), not in grant path (the **One arena, two lifetimes** note after this list).

- **The virtual offset IS the pointer.** `alloc(bytes, align)` bumps a per-LB virtual byte cursor and returns an `ArenaOffset` (a `uint32_t`) — the allocation's offset relative to the arena base. `resolve(offset)` interprets it to a physical address: `block = offset >> blockShift`, `within = offset & blockMask`, `physical = blocks[block] + within` (one shift plus one mask, the block size being a power of two). Containers store offsets, never physical pointers. The offset is the cold-path link form and is exactly what a deload image carries — being virtual, the image relocates onto an entirely different set of physical blocks with zero fixup. Physical addresses are computed on demand and never stored, compared, or dumped.
- **No straddle.** An allocation never crosses a block boundary (the cursor pads to the next boundary when a request will not fit the current block's remainder — the hot arena's rule), so every allocation is one contiguous object and `resolve` returns a single pointer. A single allocation is therefore bounded by one block; `alloc` asserts a positive length that fits a block. `alloc` aligns the cursor first; block bases are pool-aligned (`::operator new`, at least 16) and the block size is a whole multiple of any supported alignment, so the resolved address inherits the requested alignment.
- **Tail-pop is the only free.** `popTo(offset)` rolls the cursor back (last-in-first-out) and poisons the reclaimed span (`kArenaPoisonByte` = 0xCD, the cold twin of the hot 0xDD) — deleting exactly the last allocation rolls the cursor back. Interior dead space from a non-tail erase becomes a hole reclaimed only by the copying compaction (`LbMemory::reshuffle`, in the Steward section). Blocks are retained across `popTo` and return to the pool at `releaseAll` and at compaction.
- **Residency lifecycle.** `resident` / `markDeloaded` / `markResident` / `releaseAll` / `blocksHeld` / `usedBytes` track the SSD round-trip and telemetry; `markDeloaded` asserts the blocks were already returned. Lazy first-allocation (an idle arena holds zero blocks and computes no geometry — transient `Memory` objects must not consume pool blocks by existing) and the no-lock single-threaded-mutation contract round it out: per-LB state is mutated single-threaded by the phase model, the one cross-thread touch being the global manager's mutex.

The shared expression store, four ordered statement lists and seven cold string tables all ride one `LbArena` per LB — it is the whole cold substrate. Deload records the block size in its header sanity field. The determinism contract is [I-107](../30_invariants.md#i-107): offsets are deterministic (allocation order is single-threaded per LB), and physical block identity and grant order are absorbed by `resolve`. Pool exhaustion asserts naming `static_pool_bytes` ([I-95](../30_invariants.md#i-95)), never a fallback.

**One arena, two lifetimes.** Since there is a single `LbArena` and a single cold grant path (`acquireBlock`); the former HOT mode (`Mode`, `initHot`, `acquireBlockHot`, the reserve cap, `kHotPoisonByte` 0xDD) and its segregated ledger are DELETED ([D-185](../40_decisions.md), retiring [I-96](../30_invariants.md#i-96)). The bump core is identical for every user; they differ only in LIFETIME. The per-LB store carries the deload round-trip (residency flags) and the copying compaction; the per-worker scratch + sealed arenas use the byte-bump `allocBytes` (a resolved `alloc`) + `mark` / `rewind` / `reset` / `releaseAll` reclaim and are RELEASED per worker task / before the barrier (never deloaded or compacted). Everything poisons with the one `kArenaPoisonByte` (0xCD).

## ArenaVector — the arena-backed vector

`ArenaVector<T>` ([`memory_infra/arena_vector.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/arena_vector.hpp), header-only) is the first container type built on `LbArena` and the arena-backed replacement for `std::vector<T>` (`static_assert`s trivially-copyable, ≤16-byte-aligned elements — raw element bytes stream to SSD on deload). It realises the "scattered elements" model: each element is its own `LbArena` allocation (scattered, interleaved with every other container's), and a **two-level spine** — a directory of fixed 1024-offset chunks, all `ArenaOffset` runs in the same arena — indexes them. `operator[](i)` splits `i` into `(chunk = i >> 10, within = i & 1023)`, resolves the directory to the chunk and the chunk to the element: two index resolves plus the element resolve, all O(1). The two-level spine holds arbitrarily many elements despite a single allocation being capped at one block — the directory is itself ≤ one block (≤ 65536 chunks ⇒ ≤ ~67M elements; `LbArena::alloc` asserts beyond, far past any real LB). The two-level shape replaced a single-level spine that asserted on the Gauss batch's >65536-element statement vectors. The directory and chunks grow by reallocation (the old run becomes a hole the compaction reclaims); `erase` shifts the 4-byte spine offsets, not the payloads.

Deliberate `std::vector` API **subset** — `push_back` / `size` / `empty` / `operator[]` / `erase(index)` / `clear` / `release` / copy-assign (cross-arena deep copy, the LB-clone path) / assign-from-`std::vector` (scope-teardown rebuilds) / `appendSpanBytes` / `bulkAppendBytes` (the canonical element-stream deload) / `liveBytes` (the compaction gate's input). NO `data`, NO iterators, NO `swap`: their absence makes the compiler enumerate every consumer still assuming contiguous storage. There is NO mutable `operator[]` — in-place element writes are impossible through the public surface, so the skip-unchanged deload contract is airtight. **`size` and `empty` assert residency like the element accessors** — a deloaded container reads as empty in RAM, and a silent size-0 answer turns loops over it into silent no-ops while the LB's RAM-resident side tables stay mutable (the registry/levels pairing corruption the tier-1 gate caught); cold metadata comes from `Memory::deloadedCounts` instead, recorded per container at deload (`Memory::intEncodedStatementsCount`). Element references are stable across growth while the LB is resident (an element never moves; a directory growth copies the offset values verbatim) — they die at `clear` / `release` / a preceding `erase` and at compaction. The deload stream is byte-identical regardless of fragmentation, so reload rebuilds the scattered elements and the spine fresh. Unit-tested ([`src/tests/test_arena_vector.cpp`](../../../GL_Quick_VS/GL_Quick/src/tests/test_arena_vector.cpp)); ordinary scratch statement vectors use `PagedVector`, while persistent statement lists use `SharedExpressionList` and the common `IntStmtView` interface.

## IntStmtView — the phase-2 statement view

Arena storage is scattered, so it cannot hand out a contiguous `data` pointer. The phase-2 request-generation pipeline takes `IntStmtView` ([`memory.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory.hpp), alternative pointers to `PagedVector<IntEncodedExpr>` or `SharedExpressionList`, plus a cached element count, by value) and indexes through an inline `operator[]` that resolves the selected vector row or shared record: `filterIntEncodedStatements`, `makeMandatoryEncodedStatementLists1/2Static`, `generateEncodedRequestsStatic`. ## LbMemory — the growable per-LB aggregate

[`memory_infra/lb_memory.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/lb_memory.hpp) (its element type `IntEncodedExpr` sits beside it in [`memory_infra/int_encoded_expr.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/int_encoded_expr.hpp)). One `LbMemory` bundles the LB's `LbArena` (the member `manager`, declared FIRST — the arena-backed containers must destruct before the arena whose blocks back their storage) with every statified container. Its growth contract is user-required: adding a future container is ONE member + ONE appended `ContainerTag` + ONE line in each `visitContainers` overload; the deload format and all machinery built on the visitor never restructure. `ContainerTag` is **append-only** — tags are the on-disk identity of each container, never renumbered/reordered/reused. `visitContainers` (const + mutable) enumerates members in ascending tag order and is the single source of container enumeration. Tier 1 exposes the four shared-reference statement lists (tags 0–3: `intEncodedStatements`, `intLocalEncodedStatements`, `intLocalEncodedStatementsDelta`, `intExternalStatements`), all exposed on `Memory` as pure reference aliases. ## Deload — the canonical SSD file format

> **Two formats.** There are now TWO deload formats (`D-195`): this **v3 canonical** element stream — used for the DISCHARGE drain and the chapter-export reads, where the [I-103](../30_invariants.md#i-103) canonical-bytes doctrine stays intact — and the **v4 raw arena image** for the eviction/reload hot loop (nondeterministic bytes, content-complete logical state), covered in [Raw arena image (v4)](#raw-arena-image-v4--the-near-memcpy-eviction-datapath). Load dispatches on the recorded `Memory::deloadKind`. This section describes v3.

[`memory_infra/lb_deload.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/lb_deload.hpp) / `.cpp` (`gl::lbdeload`). `dumpLbMemory` streams the aggregate's containers **element-by-element in logical order, containers in tag order** — the byte stream is a pure function of logical content, independent of arena fragmentation and allocation history ([I-103](../30_invariants.md#i-103)). This IS the approved "straightening": `loadLbMemory` rebuilds element-by-element onto a fresh consecutive arena (fresh offsets).

- **File set.** Payload split into chunks of at most the block size (production) — one file per repacked block, `_n_of_N` in the name per the approved model; an empty aggregate writes one header-only file. Every file is self-describing ([D-154](../40_decisions.md#d-154)): magic `GLDL`, version (3), kind (base / tail), the per-LB **deload ordinal** (int64 — the file-name identity field), part n/N, block bytes, per-tag directory (tag, element size, element count), full chain string verbatim, then the chunk. All fields fixed-width little-endian (every GL target is x64 LE).
- **File names.** `lb<ordinal>_[t<k>_]<n>_of_<N>.bin` — a per-LB **deload ordinal** (a process-monotonic counter, `GlobalMemoryManager::assignDeloadOrdinal`) is the file's injective identity; it replaced the FNV chain hash, so a name collision is impossible by construction (LB chains contain `>` / `*`, illegal on NTFS, and exceed path limits, so the raw chain was never a usable name). The full chain lives in the header **verbatim** (the real load-time identity check) plus `registry.txt` (`<ordinal>\t<chain>`, ascending; for humans / post-run inspection only — reload uses the file lists recorded at dump time, never the registry). The ordinal is **lifetime-stable per LB**: `Memory::ensureDeloadOrdinal` assigns it once and reuses it for every re-dump and tail (`_t<k>_`) set, so a base+tail set shares one identity. It is stamped single-threaded at the kernel barrier (discharge enqueue, eviction-plan build, the pre-pass before the parallel synchronous-eviction sweep) before any worker-self-service or steward dump runs, so both possible dumpers name the file from the same stored ordinal (cross-run deterministic — a fresh process counts from 0). The counter + registry live on `GlobalMemoryManager` (the unit tests dump without an `Prover` in scope). Replaces the former hash-named scheme whose chain-collision risk, though astronomically small, was a real tail risk; the verbatim-chain header assert still catches a chain/tree mismatch at reload.
- **Loud loading.** `loadLbMemory` asserts every header field (magic, version, ordinal sign, verbatim chain — the real identity check, part numbering, block bytes, cross-part directory consistency, element sizes vs compiled-in types) — a mismatch is a corrupted or foreign file, stopped at its origin.
- **Purge.** `purgeDeloadDirectory` empties at **batch start only** (end-of-run files stay for post-run inspection); it asserts the directory name contains `"deload"` before its recursive delete. `.deload/` is gitignored — trace dumps never go into git.

**`Memory`-level composition** ([`memory.cpp`](../../../GL_Quick_VS/GL_Quick/src/memory.cpp)): `Memory::deloadStaticContainers` = dump (canonical stream, chunked at the block size) → `release` every statified container → `manager.releaseAll` → `markDeloaded`; the file set + chain land in `Memory::deloadFiles` / `deloadChain`. `Memory::ensureLoaded` = defined no-op when resident; else assert the chain still matches the tree position (`gl::buildLbChainString` — the full parent chain is the LB identity, Rule 12), `markResident`, rebuild element-by-element onto a fresh consecutive virtual index. Touching deloaded storage anywhere else asserts ([I-111](../30_invariants.md#i-111)).

## Lifecycle wiring — who deloads, who reloads

- **Deload**: the LAST act of `proveKernel` ([D-155](../40_decisions.md#d-155)) — after the phase-3 join and every post-join drain (`activateZeroCondition`, `updateGlobal*`, the compaction flush) — now under the **eager discharge drain** ([D-486](../40_decisions.md#d-486), narrowing the pressure-lazy [D-156](../40_decisions.md#d-156)); active LBs still move only under pressure. An LB that left the active set this iteration takes the **discharge protocol** (`Memory::dischargeStatementContent`, [D-157](../40_decisions.md#d-157)): flag `dischargedForever`, capture the exact registry pair set (`dischargedRegistryKeys` — the post-prove equality-node gate's probe target), empty the dischargeable containers (the cold string + validity-metadata tags survive — `LbMemory::survivesDischarge`), run the copying compaction (`LbMemory::reshuffle`) — **every block except the surviving cold-string tables' returns at the barrier, zero I/O** (the emptied statement storage was only arena holes) — then join `Prover::pendingDischarge` in deterministic `active` order for the steward's canonical dump of its survivors ([I-112](../30_invariants.md#i-112): deactivation is permanent — no reactivation path exists, `smashMail` never touches `isActive`, `ensureLoaded` asserts against the flag, and the induction zero-condition wake — a first activation of a block parked at birth — asserts against it too; the chapter export's `ensureLoadedForRead` is the one sanctioned READ-ONLY reload of a discharged LB, [D-158](../40_decisions.md#d-158)). The barrier installs the pending list and wakes the steward at once: its drain writes each survivor set as one canonical image via `Memory::deloadStaticContainers` in the background while the next iteration runs (frozen content, blocks never needed again), returns the blocks, and trims the main pool to the shared reuse reserve `kRecycledWarmBytes`; the next barrier folds the drained entries out. Active-LB relief is the working-set pager's (see the Steward section below). **A run that never discharges an LB writes ZERO deload files without pressure. Stable active LBs touch no deload machinery at all.** `pendingDischarge` resets at batch start with the registry. `Memory::dumpStaticContainers` / `releaseStaticBlocks` remain as the split primitives for the steward's active-eviction handshake (next step). Below pressure, resident LBs keep their blocks and the next phase-1 `ensureLoaded` is a no-op — zero reload I/O for stable LBs; the pool stays the hard memory bound (exhaustion still asserts). Block counts are logical and read at the single-threaded barrier, so the pressure decision is deterministic across runs. Dump walks each container element-by-element (`ArenaVector::appendSpanBytes`) and reload rebuilds element-by-element (`bulkAppendBytes`) — the scattered layout forces the per-element walk, but the byte stream it produces is the canonical content stream. The `registry.txt` (`<ordinal>\t<chain>`, fed from `GlobalMemoryManager::deloadRegistry`, cleared at batch start) is rewritten single-threaded, and only on iterations where something was dumped. **Skip-unchanged contract**: every statified container mutator sets `LbMemory::dirty`; a deload with the flag clear releases the blocks without rewriting (the on-disk file set still equals the in-memory content — both branches defined results, cache-valid/cache-stale). The state clears at dump and at reload, the two points where RAM == disk by construction; in-place element writes are impossible by construction (`operator[]` is const-only; the only writers are the marking mutators). **Tail-delta + threshold compaction** (the WAL/journal pattern): an `AppendedOnly` window dumps just the new rows as a `kind = 1` tail file set (`_t<k>_` names); a restructuring mutation, tails reaching base/`kTailCompactionDenominator`, or `kMaxTailSets` tail sets force the next full canonical rewrite — which is where the straightening re-canonicalizes the image. Reload applies base then tails in recorded order. The CE filter never enters `proveKernel`, so clone LBs never deload. Mid-iteration-created LBs stay resident until the end of their first active iteration.
- **Reload touch points (the complete list; kernel-side reloads go through the CLAIM-CORRECT DOOR — `claimAndLoadForWork` + release-`Idle` — never a bare `ensureLoaded`, [D-196](../40_decisions.md#d-196))**: the worker handshake at phases 1/2/3 entry + the phase-2 finalize re-claim; the steward executor's prefetch-load task + the barrier head prefetch (claim-protected); the BARRIER SEAM doors — the commit-barrier mail sweep (its own dispatch-cursor window over `bodies`), the `updateGlobal` / `updateGlobalSingleChapter` cross-LB `nextIterationInternalMail` deposits and the deferred-ancestor admission drain (all under the pinned-cursor seam window over `active`), and the barrier discharge reload before `dischargeStatementContent` (post-quiesce); the post-prove visualizer equality-node read — LIVE nodes only, bare `ensureLoaded` sanctioned (steward destroyed, no pager; a discharged node's gate probes `dischargedRegistryKeys` instead; the recursion-node gate probes the `intLocalEncodedStatementsSet` mirror and reloads nothing); **`buildStack` entry** — `ensureLoadedForRead`, the chapter export's read-only reload that is also legal on DISCHARGED LBs (their origin history lives in the cold string tables since the strings campaign; [D-158](../40_decisions.md#d-158)). A new firing residency assert means a new between-iteration/post-prove reader exists — extend THIS list with an explicit door (kernel-side) or `ensureLoaded` (post-prove), never lazy-load.
- **Safe-while-cold reads**: NONE on the containers themselves — `size`/`empty` assert residency exactly like element access. The only legal cold metadata is `Memory::deloadedCounts` (recorded at deload; `intEncodedStatementsCount` serves the per-burst `total_exprs` reporting).
- **Purge**: top of `analyzeExpressions`, batch start only; `.deload/` keeps the run's last images for post-run inspection.
- **Honest scope** ([G-51](../50_gotchas.md#g-51)): active LBs are resident for the whole iteration; the tier-1 win is idle-across-iterations LBs and the between-iteration footprint.

## Steward — the background memory custodian

[`memory_infra/steward.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/steward.hpp) / `.cpp`. The steward is the background memory custodian that takes deload execution off the kernel's critical path — a PLANNER thread plus an I/O EXECUTOR pool ([D-196](../40_decisions.md#d-196)). **Decision/execution split**: the kernel barrier DECIDES (single-threaded, on quiesced logical counts), the steward EXECUTES asynchronously while the next iteration computes ([D-159](../40_decisions.md#d-159)).

- **Planner/executor split.** The planner (the steward's original thread, `threadMain`) runs the 200 µs window poll and ENQUEUES I/O tasks; `steward::ioThreadCountFor(workers, kIoThreadsOverride)` executor threads (= `clamp(workers/8, 2, 8)`, 4 at 32 workers; the override constant set to 1 serializes the pool to isolate a concurrency bug) drain two fixed 256-slot rings (`kIoRingCapacity`) under the steward mutex: HIGH = prefetch loads, LOW = evictions + reshuffles, HIGH first EXCEPT below the emergency floor (then LOW first — evictions must not starve behind reloads with no blocks to land in). Task execution is claim-first drop-on-lose; eviction/reshuffle tasks re-validate their window at execution via the monotone `windowGeneration_` + a kept-range check under the CURRENT cursor. Enqueues dedup by (kind, LB); a full ring DROPS the enqueue — designed load-shedding, counted (`prefetchDroppedFullRing` / `evictDroppedFullRing`), re-planned on the next pass. The ASYNC DUMP CONTRACT rides the LOW lane: an eviction task holds the LB `Busy` and its blocks until the raw image write completes, releases, THEN stores `Dumped` — never observable half-written; in-flight blocks/bytes are exposed (`inFlightBlocks` / `inFlightBytes`) and the planner's reserve projection counts them as freed-but-unavailable. `quiesce` = planner parked + rings empty + executors idle (LOAD-BEARING: the barrier's `deloadRegistry` reference read for `rewriteRegistry` races executor dump registrations without it); `stop` joins the pool. The planner's ONE remaining I/O is the discharge drain, verbatim on its thread ([I-106](../30_invariants.md#i-106) execution unchanged). Each executor owns a private compaction scratch `LbArena` from `lbMemory`. **The between-iterations SEAMS are windowed too** ([D-196](../40_decisions.md#d-196)): the commit-barrier mail sweep runs under its own dispatch-cursor window over `bodies`, and the post-join deposit drains run under a window over `active` with the cursor pinned at 0 (the honest Belady origin between iterations — the next use of `active[i]` is position `i`), both under phase id 4 (the barrier telemetry bucket) and both closed before the discharge barrier block; every seam reload goes through the claim-correct door, so a `Dumped` claim can never cover a resident arena (asserted at the door). **Prefetch loads are BUDGETED** (`kPrefetchBudgetBlocks` = reserve / `kPrefetchBudgetDivisor`): pending HIGH-lane loads, estimated from `lastRawImageBytes`, are capped below the reserve at both issue sites (`prefetchHead` and the planner's per-pass enqueues) — an executor load task has no valve and, at seams or teardown with no window open, no eviction relief either, so the pending loads must always fit inside the reserve's free blocks. At prove's teardown the scope guard first **discards every queued-but-unstarted ring task** (`discardQueuedIoTasks` — there is no next iteration to warm; defined load-shedding) and clears the exhaustion reporter only at its END, so a teardown exhaustion prints a full census.

- **Watermark band** — wake at `steward::kWakeNum/kWakeDen` (1/2 of the pool), evict down to `kStopNum/kStopDen` (2/5), park; the kernel's `kReleaseHighWaterNum/Den` (3/4) synchronous path stays as the hard bound (`static_assert`ed strict ordering stop < wake < hard bound; [D-160](../40_decisions.md#d-160)).
- **Grant ledger** (`GlobalMemoryManager::grantsSinceBarrier`, reset at the kernel barrier) with its one-shot crossing trigger (`armGrantTrigger`) — the only legal mid-iteration pressure signal ([I-106](../30_invariants.md#i-106)).
- **Barrier protocol** (`MemorySteward`): disarm previous trigger → `quiesce` (every released drain completes — quiesced counts are logical again) → fold the drained discharge handoff → discharge this iteration's INACTIVE LBs (reload-if-cold, then `dischargeStatementContent`) → hand the discharge list to the steward and `wake` it (the eager discharge drain of main batches, [D-486](../40_decisions.md#d-486): the drain dumps, returns the blocks and trims the main pool; the root and the incubator anchor LB, which still receive post-join drain mail after their discharge, are never handed to it). An incubator batch wakes it only at the watermark and otherwise arms the grant trigger ([D-551](../40_decisions.md#d-551)). Active-LB pressure is no longer a barrier decision — the working-set pager handles it continuously in the phase windows; the barrier's old synchronous hard-bound active mass-deload and the eviction-plan builder are removed ([D-161](../40_decisions.md#d-161)).
- **Scope**: one steward per `prove` call (scope guard: start with the worker count before the first kernel, quiesce + stop after the last — `stop` joins the executor pool); CE filter and `destroyGrid` never see it. The discharge drain touches only discharged LBs — disjoint from the phase sweeps; the pager's executor tasks touch ACTIVE LBs, arbitrated exclusively by the per-LB claim word ([I-122](../30_invariants.md#i-122)); the only sanctioned cross-thread shares are the pool mutex on block traffic and the relaxed `DeloadStats` atomics. Steward-side asserts (planner or executor) abort the process (Rule 19).

- **Stuck-assert — the forward-progress backstop** ([I-113](../30_invariants.md#i-113)): every worker wait for an LB is deadline-bounded (`steward::kStuckSeconds`, 30 s). The unified handshake `claimAndLoadForWork` (all three phases) stamps a steady-clock start and, if a `Busy` wait (the steward mid-op on this exact LB) outlasts the deadline, prints the stuck LB's full chain and asserts (Rule 19) instead of spinning forever — closing the silent-freeze failure mode of the removed `waitWhileThrottled` gate. A safety tripwire (its firing is timing-dependent), never a proof input.

- **Working-set pager — RAM is a cache of the working set** ([D-161](../40_decisions.md#d-161), [I-114](../30_invariants.md#i-114), reserve-target drain per [D-197](../40_decisions.md#d-197)): the active-LB deload/reload policy, identical in all three phases. Each phase opens the same window (`beginPhaseWindow` over its dispatch cursor + the active vector; `endPhaseWindow` at the join). While open, the planner pass `maintainWorkingSet` PLANS (the executor pool executes — see the planner/executor bullet above): (1) PREFETCH tasks over the **unified** prefetch region `[cursor, cursor+workers+kLookaheadWorkerMultiple·workers)` — starting AT the cursor and ending exactly where the keep window ends — reload a cold upcoming LB, reshuffle a fragmented resident one — and (2) EVICTIONS toward a free-block **RESERVE** (`kReserveBlocks` = 2048, sized to cover the largest mid-burst transient grant burst — sealed page sets + CE clones, the census's UNATTRIBUTED bucket, measured ~2400 blocks — because standing free headroom is what protects the pure-grant path between valve firings; since [D-422](../40_decisions.md#d-422) every main-pool grant that would leave fewer free blocks than the emergency floor first runs the grant-time valve `MemorySteward::relieveGrantPressure`, which evicts one behind-cursor victim, so growth inside a claimed block is throttled to the eviction rate): while the PROJECTED free blocks (live free + in-flight dump blocks + already-queued eviction blocks) fall short of the reserve and an eligible farthest-next-use victim exists, plan one more; the pass ends when the projection meets the reserve, no victim qualifies (a DEFINED result — the working set fits and the stream pauses; genuine exhaustion still asserts at `acquireBlock`, Rule 19), or the ring fills (designed load-shedding, counted, re-planned next pass). Victim selection is TWO-TIER (`pickVictimTwoTier`, [D-196](../40_decisions.md#d-196)): tier 1 is the floor-preferred Belady scan (`pickVictimBehindCursor` — cyclic next-use distance `d(i)=(i−cursor) mod n`, a backward scan from `keepLo−1` with wraparound visiting strictly decreasing `d`, so the first eligible hit is the farthest-behind; floor `blocksHeld >= kMinEvictBlocks` (4) — tiny LBs stay implicit residents; minimizing the eviction count matters as much as picking the right victims); when the reserve is breached and NO above-floor victim exists, tier 2 re-runs the SAME scan with a one-block floor — the survival branch: a floor-only drain finds no victim in the median-2-block early-batch population while grants continue (the post-pager 4 GiB wall). Eligible = active, unsplit, resident, `Idle`, outside the kept working set `[cursor−workers, cursor+workers+kLookaheadWorkerMultiple·workers)`. This REPLACES the former watermark drain (mass-evict at 3/4, one-for-one at 1/2, `pickBiggestDeloadable`), which starved eviction victims and hit the `IncubatorPeano1` exhaustion assert at 4 GiB — behind-cursor victims are always available (the just-processed LBs), curing the starvation; the biggest-first selector `pickBiggestDeloadable` is retired entirely (`evictOneForReload` also picks two-tier behind-cursor). The prefetch region and the keep window share the END `keepHi`, so a freshly prefetched LB is inside the kept set and is never drained by the same pass (the asymmetry the unification fixes: the old prefetch region sat outside the old keep window when `workers > kLookahead`; `kLookaheadWorkerMultiple = 2`, so the lookahead now scales with the worker count; the window width multiplies the concurrent load-side block demand, which must stay under the emergency floor for the LOW-lane priority flip to protect the pool — a wider window exhausted a 4 GiB pool with massive evictable supply present, so any future widening must scale the emergency floor with the window). Workers self-load through the unified handshake `claimAndLoadForWork` (claim the LB, then `ensureLoaded` into the reserve's free blocks) — the handshake also carries the **widened worker pressure valve** ([D-196](../40_decisions.md#d-196)): EVERY claim checks `freeBlocks` against the emergency floor `kEmergencyFloorBlocks` (reserve/2) and, on breach, evicts ONE behind-cursor victim (counted, `emergencyEvictCount`; the cold-miss path adds the reload-fit trigger), giving the pure-grant path (scratch / statement growth with no reload) the valve it previously lacked — and **release the claim the instant they are done with the LB** so the steward can reclaim it — phases 1/3 at the body end, phase 2's executor when the LB's last part seals (a per-LB remaining-parts counter; the finalize then re-claims + reloads it). A processed LB left `WorkerOwned` would never drain and the resident set would grow to ALL active LBs (the first-run `IncubatorPeano1` pool depletion before this release was added). **The claim word, not the index window, is the correctness guarantee** — the steward CASes `Idle → Busy` before any deload, so a worker's claim makes that CAS fail and an in-flight (`WorkerOwned`) LB is NEVER deloaded. Phase 2 registers its REAL dispatch atomics ([D-196](../40_decisions.md#d-196)): per pass, an EXECUTOR window over the pool's `next` atomic + the flat `execOrder` task vector (split-part duplicates collapse via dedup + claim CAS; split LBs are ineligible victims anyway), then a FINALIZE window over `nextLi` / `toRun` — the frozen `phase2Cursor` is retired, and the two sequential sub-windows keep `DeloadStats`' single-window pairing (both report as phase 2). The barrier additionally calls `prefetchHead` — one-shot `kAnyWindowGeneration` HIGH-lane loads for the next iteration's head `[0, window width)`, after the discharge decision, killing the phase-1 cold start (inactive heads skipped; safe against `dischargedForever` because the barrier quiesce empties the rings before the flag is ever set). This replaces the former DISABLED barrier-armed eviction plan (the `Planned` state + the second `burstClaim` word are retired); the reason that plan was off — the residency-gated deactivation survey dropping theorems — is fixed ([D-149](../40_decisions.md#d-149)), so active-LB deload/reload is content-invisible and the timing-dependent eviction set never changes proof output. **Inert without pressure:** when `freeBlocks >= kReserveBlocks` nothing is evicted → nothing reloads, so light batches (Peano main) and the whole pipeline at 8 GiB (peak « total − reserve) run exactly as before. **The active-LB eviction dump is the v4 RAW image** (`deloadStaticContainersRaw`; the executor eviction task `executeIoTask` + the worker valve's `evictOneForReload`), reloaded raw on next touch — see [Raw arena image (v4)](#raw-arena-image-v4--the-near-memcpy-eviction-datapath); the discharge drain stays canonical v3.

- **Reshuffle — per-LB copying compaction** ([D-162](../40_decisions.md#d-162)): `LbMemory::reshuffle` is the copying (semi-space / Cheney-style) collector that reclaims the arena's interior holes — an in-RAM round trip through the same canonical element stream the deload uses: capture each container's content (`appendSpanBytes`) into heap buffers in tag order, `release` every container and `manager.releaseAll`, then rebuild each from its buffer (`bulkAppendBytes`) onto a fresh dense arena, returning the emptied blocks to the pool — relief tail-pop alone could never produce. Gated by the dual AND test `steward::needsReshuffle`, fed on the paged arena by `steward::arenaNeedsCompaction`: free pages parked inside held blocks ≥ one block AND ≥ 1/8 of the held span ([D-420](../40_decisions.md#d-420); the former byte-cursor figures were zero on paged arenas and never fired). Content-invisible: logical content, element order, string ids, and the dirty state are all unchanged — only the (unobservable) offsets are reassigned, so a compaction never forces a deload rewrite. The transient heap spike is the live content size (the semi-space cost); runs only under exclusive LB access (steward claim or single-threaded barrier), never mid-burst.

- **Mid-burst throttle relief — RETIRED** ([D-161](../40_decisions.md#d-161); was [D-148](../40_decisions.md#d-148) / [I-115](../30_invariants.md#i-115)): the phase-2 `waitWhileThrottled` gate + `forceDeloadPass` + the relief window are removed — the gate's pre-allocation wait was the silent-freeze deadlock (a worker parks before any `acquireBlock`, so when nothing is force-deloadable the exhaustion assert never fires). The working-set pager subsumes mid-burst relief: a phase-2 worker that needs room evicts a deloadable LB inline (`evictOneForReload`), and genuine exhaustion asserts at `acquireBlock`, never a wait. The `GlobalMemoryManager` throttle band and the `burstClaim` word are now removed entirely.

## Deload telemetry — `DeloadStats` and the `[DELOAD]` lines

The deload/reload datapath is instrumented by one process-wide telemetry aggregate, `DeloadStats` ([`memory_infra/deload_stats.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/deload_stats.hpp) / `.cpp`, `gl::deloadStats`). It is **pure telemetry — never a prover input** (Rule 16 / [I-44](../30_invariants.md#i-44)): the deload set, the eviction victims, and the theorem output are all independent of every value it holds; the forthcoming ASIC / fast-PC build runs the proof without it. All counters are `std::atomic<int64_t>` written with relaxed ordering (a monotone counter, read only by the single-threaded end-of-batch report) and timers use `std::chrono::steady_clock`. Recording lands only where an operation is already slow (dump / load / reload-index-rebuild / eviction / worker self-load / Busy-claim wait); the resident fast path costs one relaxed increment.

- **Counters.** v3 canonical dump/load bytes+ns+count (`lbdeload::dumpLbMemory` / `dumpLbMemoryTail` / `loadLbMemory`); **v4 raw dump/load bytes+ns+count + `rawLoadPeakNs`** (`recordRawDump` / `recordRawLoad`, the near-memcpy eviction datapath — see [Raw arena image](#raw-arena-image-v4--the-near-memcpy-eviction-datapath); the peak is the reload cost model's worst case); the reload-only throw-away index rebuild ns+keys **+ call count** (`indexRebuildCount` — the v3-only `KeysView::bulkAppendBytes` → `rebuildIndex` hook; a v4 raw reload rebuilds NO index, so this counter staying flat across a raw reload is the proof the bucket pages were preserved verbatim); the three-way `Memory::dumpStaticContainers` decision (skip-clean / tail-dump / full-dump counts); the steward working-set-pager evictions (count / blocks / dump-ns, in `MemorySteward::maintainWorkingSet`); prefetch issued (steward reload) / hit / miss (worker-side in `MemorySteward::claimAndLoadForWork`); worker self-load ns+count and inline-evict ns+count plus `emergencyEvictCount` (the counted emergency-fallback evictions in `claimAndLoadForWork` — expected 0 under the reserve model, a nonzero count is the alarm the reserve is undersized); and per-phase Busy-claim wait ns+count (bucketed by the `phase` parameter threaded onto `claimAndLoadForWork` and `beginPhaseWindow`).
- **Per-phase `[DELOAD]` line.** `MemorySteward::beginPhaseWindow` / `endPhaseWindow` (kernel thread, single-threaded around each phase join) open and close a snapshot window in `DeloadStats`; at each close, if the phase moved any deload traffic, one line prints to the common diagnostics log (, batch- and hashburst-marked) — `[DELOAD] phase<k>: out <GiB> @ <GiB/s> | in <GiB> @ <GiB/s> | worker-wait <ms> | self-loads <n> | inline-evicts <n>` — the thick SSD stream made visible per phase (wall time = the window's own duration). The `out` / `in` totals FOLD BOTH streams: v3 canonical (discharge) and v4 raw (eviction), so on the working-set-pager phases the raw eviction traffic is what the line reports.

## Raw arena image (v4) — the near-memcpy eviction datapath

The v3 canonical element-stream is a pure function of logical content ([I-103](../30_invariants.md#i-103)) but slow to write and read: each dump walks every element into a heap payload, each reload rebuilds every container element-by-element AND re-hashes and re-probes every cold-map key to rebuild the throw-away index. Measured on worker threads the v3 reload runs ~0.06–0.07 GiB/s. For the eviction/reload HOT LOOP (active LBs the working-set pager cycles under pressure) that cost is the bottleneck; the **v4 raw arena image** replaces it with a near-memcpy stream.

**The insight.** Every deloadable container packs its elements into `allocPage` pages of the ONE `LbMemory::manager` arena — the four statement `PagedVector`s, the cold-map key/value stores, AND the throw-away `PagedHashIndex` bucket arrays all ride that single arena's page tier. Container SCALAR state (`size_`/`rootVid_`/`numPages_`/geometry) lives in the never-deloaded `Memory` shell, not the arena. And vids are position-independent handles resolved through `pageAt` per access ([I-107](../30_invariants.md#i-107)). So a byte image of the live pages, in ascending vid order, plus a bitmap of which vids are live, is a COMPLETE image of the deloadable state — and restoring it (bind the same vids to freshly-carved DENSE pages, refill the bytes) leaves every container resolvable with ZERO container work: no element walk, no `rebuildIndex` (the bucket pages come back byte-identical). One copy total.

**The C1 primitives** ([`memory_infra/lb_arena.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/lb_arena.hpp) / `.cpp`):
- `LbArena::rawShape` → `RawShape { blockBytes, pageBytes, byteBumpCursor, vidCount, livePages }` (the v4 header scalars; `byteBumpCursor` is `cursor_`, expected 0 — every deloadable container is page-tier, no `ArenaVector` members / no direct `manager.alloc`, but the format carries a nonzero byte-bump span raw so a future byte-bump container is supported).
- `LbArena::fillLiveBitmap(bitmap, bytes)` → one bit per vid, set iff live (interior dead-vid holes preserved).
- `LbArena::emitRawImage(Sink&&)` — heap-free: the byte-bump span (usually absent) then the live pages ascending vid, coalescing physically-adjacent source pages into one `sink` call (write-count only; the payload is always `livePages * pageBytes` bytes in ascending-vid order).
- `LbArena::restoreForRawLoad(vidCount, liveBitmap, liveCount, byteBumpCursor)` — bulk-acquires the blocks (one mutex batch), binds the k-th ascending live vid to dense slot k (the reload self-heals fragmentation), nulls the dead vids, rebuilds the free-list, `assertInvariants`. Asserts the arena is empty (restore on a non-empty arena is a bug, Rule 19).
- `LbArena::fillRawImage(Fill&&)` — the mirror: reads the file bytes straight into the restored pages (dense slots, ascending vid, coalescing physically-adjacent DEST runs), one copy, no staging buffer.
- `GlobalMemoryManager::acquireBlocks(count, out)` / `releaseBlocks(blocks, count)` — one mutex acquisition per batch (the raw reload / eviction grants a whole LB's blocks at once; the per-block mutex traffic was a measured floor). `LbArena::releaseAll` now bulk-returns its two data-block directories through `releaseBlocks`.

Bytes are NONDETERMINISTIC (the fragmentation-dependent page contents and grant order leak into the file) — the [I-103](../30_invariants.md#i-103) canonical-bytes property is DELIBERATELY WAIVED for eviction images (user-approved, `D-195`) — but the RESTORED LOGICAL STATE is byte-identical (same vids → same bytes, container bookkeeping untouched), so proof output (theorems, proof graphs, verifier checks) stays deterministic.

**The v4 file format** ([`memory_infra/lb_deload.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/lb_deload.hpp) / `.cpp`). `kVersionRaw = 4`, `kKindRaw = 2`, ONE file per LB (`rawFileName(ordinal)` = `lb<ordinal>_raw.bin`, no parts, no tails). A DYNAMIC header: the `kRawHeaderPrefixBytes` (48) fixed prefix — magic, version, kind, ordinal, `headerBytes` (the total header size, a multiple of `kRawHeaderAlignBytes` = 4 KiB so the page payload stays aligned for future unbuffered I/O), block/page bytes, byte-bump cursor, chain length, vid count, live page count — then the verbatim chain (the identity check), then the live-vid bitmap, then zero padding up to `headerBytes`. The header is sufficient BY CONSTRUCTION (no capacity assert): the predecessor's fixed 4 KiB header tripped its deliberate capacity tripwire on the first big Gauss LB at 4 GiB, whose ~32000-vid bitmap alone neared 4 KiB. Heap-free on both sides: the prefix rides a stack buffer, the chain streams from the caller's string, and the bitmap + padding stream through ONE bounded 4 KiB stack chunk buffer (`fillLiveBitmapRange` fills byte-aligned bit-chunks; a shared reusable buffer was rejected — the executor pool dumps concurrently), then the raw page payload streams straight from pool memory via `emitRawImage`. `dumpLbMemoryRaw` returns the payload byte count (the per-LB `lastRawImageBytes` victim-ranking input); `loadLbMemoryRaw` asserts the prefix, verifies the chain in bounded chunks, feeds the bitmap chunks into the STAGED arena restore (`restoreForRawLoadBegin` / `Chunk` / `End`; the single-shot `restoreForRawLoad` remains as the one-chunk wrapper), and `fillRawImage`s the file bytes straight into the pages — no per-key rebuild.

**The `Memory`-level ops** ([`memory.cpp`](../../../GL_Quick_VS/GL_Quick/src/memory.cpp)). `Memory::dumpStaticContainersRaw` captures `deloadedCounts` (the only legal cold metadata), `ensureDeloadOrdinal`, Clean-skips a fresh raw base, else writes `lb<ordinal>_raw.bin`, sets `deloadFiles = { rawName }`, `deloadKind = Raw`, records `lastRawImageBytes`, clears the v3 tail bookkeeping. `Memory::releaseStaticBlocksRaw` does NO `container.release` walk (the raw win — the bookkeeping must survive for the rebind); just `manager.releaseAll` + `markDeloaded`. `Memory::reloadFromImage` DISPATCHES on the recorded `Memory::deloadKind` (`Raw` → `loadLbMemoryRaw`, `Canonical` → the v3 `loadLbMemory`) — a recorded field, so no extra file open; each loader still asserts its header version. A raw-evicted LB later discharged flips `deloadKind` back to `Canonical`.

**The teardown residency branch.** Because `releaseStaticBlocksRaw` skips the container walk, a raw-deloaded `Memory` destructing on its cold arena would drive `~PagedVector` / `~PagedHashIndex` → `clear` → `freePage` on a deloaded arena. A teardown-only residency branch IN THE DESTRUCTORS `~PagedVector` / `~PagedHashIndex` (when `!arena->resident`: reset the bookkeeping only, skip `clear`) makes that a defined no-op — a DEFINED teardown lifecycle, not defensive programming. The branch deliberately lives ONLY in the destructors, never in `clear` itself: `clear` is callable from LIVE code, and a hypothetical bug that cleared a cold LB mid-run must die loudly on `freePage`'s residency assert (Rule 19), not silently reset bookkeeping. Justified in the Doxygen against Rule 19.

**Read-path tuning + the policy interface.** The reload is already block-region-sized: `restoreForRawLoad` packs the live pages onto consecutive slots, so `fillRawImage` coalesces each physical block's worth of pages into ONE read of up to `blockBytes` (fewer, larger reads, not per-page). The policy side reads `Memory::lastRawImageBytes` (the payload byte count of the LB's last raw image, readable while deloaded) to rank eviction victims by ACTUAL image cost — the reload cost model is `lastRawImageBytes / readBW`, with `readBW` derived from the aggregate `DeloadStats` raw-load counters (and `rawLoadPeakNs` the tail). The async writer (`inFlightBytes`, the second dedicated dump thread) is a LATER subsession; the current eviction dump is synchronous on the evicting thread.

**Eviction wired to raw.** The working-set pager's active-LB eviction sites are the two the raw path serves: the executor-pool eviction task (`MemorySteward::executeIoTask`, planned by `maintainWorkingSet`) and the worker valve's inline `evictOneForReload` both call `Memory::deloadStaticContainersRaw`, and the worker reload (`claimAndLoadForWork` → `ensureLoaded`) dispatches back to raw automatically. The DISCHARGE drain (`threadMain`'s pending-discharge `work` list) and the chapter-export `ensureLoadedForRead` reads stay canonical v3, where the [I-103](../30_invariants.md#i-103) determinism doctrine stays intact. (The retired barrier-armed `Planned`/`evictionWork_` eviction plan — production-dead since the working-set pager landed, [I-114](../30_invariants.md#i-114) — was left on v3; it is exercised only by a steward unit test.) The eviction path never writes tail-deltas (the raw dump is one whole-arena image); `dumpLbMemoryTail` survives for the v3 discharge dumps that still use it.
- **Per-batch prints.** Once per batch at the first kernel barrier, `Prover::proveKernel` prints the active-LB count and the resident `blocksHeld` distribution (max / p95 / median / count-below-`kSmallLbBlocks`) — the raw inputs for later size-floor / reserve-target tuning. At batch end, right after the `[STATIC-MEMORY] peak blocks in use` line, `DeloadStats::reportSummary` prints the accumulated totals and the aggregate is then `reset` for the next batch.

## Extent file — one open file for the v4 raw eviction images (`D-198`)

The per-LB named-file raw format above (`lb<ordinal>_raw.bin`) fixed the CPU cost of eviction but left the per-OPERATION I/O fixed cost: one NTFS `CreateFile`/truncate/`close` per eviction (+ a per-file Defender scan-on-close), ~50 ms per ~2.5 MB image, almost size-independent — thousands of tiny-LB evictions per phase. The **extent file** (`parameters.enable_extent_deload`, default true; [`memory_infra/extent_file.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/extent_file.hpp) / `.cpp`) removes it: ONE preallocated `.deload/extent.bin` held open for the whole batch, each LB placed at a stable slab offset, dumped/reloaded by POSITIONED I/O into the already-open handle.

- **`PositionedFile`** — the substrate. `open`/`close`/`preallocate`/`grow`/`writeAt`/`readAt`/`fileSize`. Windows backend: each calling thread transparently gets its OWN `CreateFileW` handle (own file object → no shared file pointer, no file-object serialization lock), cached thread-locally keyed by a process-global open generation (so a reused object never serves a closed handle — the ERROR_INVALID_HANDLE trap that the commit-1 build hit and fixed); positioned I/O = `WriteFile`/`ReadFile` with a per-call `OVERLAPPED` offset (the pwrite/pread equivalent on a synchronous handle). POSIX backend: one shared `fd` + `pwrite`/`pread`. I/O failures / short transfers / growth failures all assert naming the knob (Rule 19), and so does a sizing that would push the process's total of open positioned-file bytes (this extent file and the two request-frontier spill files) past 50 GiB (`kMaxDeloadBytes`, `accountDeloadResize`; [I-350](../30_invariants.md#i-350)). The **concurrency claim was PROVEN standalone before any wiring** (`test_extent_file`, `concurrent_disjoint_offsets_no_interference`: 8 threads, each its own handle, 40 rounds of overlapping positioned write+read on disjoint 1 MiB regions, byte-verified) — Windows per-thread handles neither serialize nor short-transfer at disjoint offsets, so the fallback (handle-reuse per LB file) is unused.
- **`ExtentAllocator`** — power-of-two slab free-lists + bump high-water, all under a mutex. `allocSlab(bytes)→{offset,classBytes}` (smallest power-of-two block multiple ≥ bytes; free-list hit or bump-alloc), `freeSlab`, `reset` (offsets recycle from 0), `classBytesFor`, `allocatedBytes`/`highWaterBytes`. Each LB owns ONE slab for its active life: a stable/shrinking re-dump overwrites IN PLACE (no allocator touch — the near-memcpy hot path); a first dump or a growth past the class (re)allocates; ~3 promotions per LB over a batch. The file grow is the WIRING's job (`GlobalMemoryManager::allocateExtentSlab` serializes alloc + `PositionedFile::grow` so grow targets stay monotone under concurrent evictions), keeping the allocator unit-testable in isolation.
- **Format core sharing.** `lbdeload::emitRawImageStream` / `consumeRawImageStream` are the byte-format cores, parameterised by an image-RELATIVE positioned sink/source. The named-file `dumpLbMemoryRaw` / `loadLbMemoryRaw` (sequential `ofstream`/`ifstream`) and the extent `dumpLbMemoryRawAt` / `loadLbMemoryRawAt` (`PositionedFile& + slab offset`) share them, byte-identical — so the A/B gate compares like with like. `rawImageBytesFor` (pure header+payload size) drives slab sizing. `loadLbMemoryRaw`'s ordinal assert is TIGHTENED to `ordinal == expectedOrdinal` (the LB's `deloadOrdinal` threaded in) — the direct slab-reuse / torn-image tripwire now that ordinals share one file (the chain assert is the second).
- **`Memory` metadata + seams.** `rawExtentOffset_` / `rawExtentClassBytes_` REPLACE the raw path's `deloadFiles` (the reload seeks to the offset, reads the self-describing header); `rawExtentEpoch_` (bumped at each `openExtentFile`) invalidates a cross-batch stale slab so a persisting LB's offset is never overwritten in place after a purge. `dumpStaticContainersRaw`, `releaseStaticBlocksRaw`, and `reloadFromImage` branch on `staticMemory.useExtent`: extent path uses the slab, named path uses `deloadFiles`. `dischargeStatementContent` frees the slab (Raw→Canonical, never raw-reloads again — the one new discharge line). The RELEASE side mirrors the reload's dispatch: `Memory::releaseStaticBlocksDispatch` routes `deloadKind == Raw` → `releaseStaticBlocksRaw` (no container-release walk — the bookkeeping must survive the raw rebind, and an extent LB has no named file set) and `Canonical` → the v3 `releaseStaticBlocks`; the chapter export's per-theorem G-53 release loop uses it (the hardwired v3 release there fired the "without an on-disk image" assert on the first extent-raw export reload at 4 GiB, and was latently wrong for ANY raw LB the export revisited — the v3 walk resets the bookkeeping the rebind needs). Same-format dump+release compositions keep calling their own path; both paths' preconditions stay asserted unweakened.
- **Lifecycle + ownership.** `GlobalMemoryManager` owns the `PositionedFile` + `ExtentAllocator`. `openExtentFile` (batch start, after `purgeDeloadDirectory` — closed first so the purge can delete the old file) preallocates 1.5x the pool, inits the allocator, bumps the epoch. The file is closed at the NEXT batch start — AFTER this batch's chapter export, whose post-prove raw reloads of still-live equality nodes read the extent file, so it must outlive the steward. Purge = truncate + allocator `reset`; offsets recycle from 0 (deterministic per batch). Grow = 256 MiB-chunk `SetEndOfFile`/`ftruncate`; extent-full is the disk, which asserts naming `kExtentInitialBytes`.
- **registry.txt.** Extended to `<ordinal>	<extentOffset>	<slabBytes>	<chain>` (`-1	0` for slab-less LBs — v3-only, discharged, or extent off), fed by the manager's per-ordinal slab registry (`extentSlabRegistry`, recorded at `allocateExtentSlab`, dropped at `freeExtentSlab`). Human audit only — reload never reads it, exactly as before.
- **Telemetry.** `extentLiveBytes` (Σ Dumped raw-LB image bytes, a per-LB delta on each dump, batch-scoped on the manager not `DeloadStats`), `extentAllocatedBytes` (Σ slab class sizes), `extentFileBytes` (file high-water) print beside `[STATIC-MEMORY]`: alloc/live = internal slack, file/alloc = free-list + preallocation overhang.

Extent offsets are nondeterministic (allocation order) but v4 raw BYTES were already nondeterministic ([D-195](../40_decisions.md#d-195)) and offsets never enter proof output — no new determinism issue. See [D-198](../40_decisions.md#d-198).

## Scratch string arenas — the per-worker half of string statification

[`memory_infra/scratch_arena.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/scratch_arena.hpp) / `.cpp`. The string statification campaign splits strings into two classes: **ColdString** — persistent per-LB content (the interner backings), statified and deloadable with the LB — and **ScratchString** — transient calculation strings in per-worker bump arenas, never deload-registered, RELEASED per worker task. (Originally a separate HOT substrate; the campaign folded it onto the cold grant path — [I-124](../30_invariants.md#i-124).)

- **`ScratchArena` is `using ScratchArena = LbArena`** — the shared bump arena (LbArena section) on the COLD grant path, not a second implementation. **One per worker slot**, indexed by the `coreId` every executor entry point receives (`ScratchArenaRegistry`, a `std::deque<LbArena>` `bind`-ed cold per slot; process-wide via `scratchArenas` / `initScratchArenas`, initialized in the `Prover` constructor). NOT `thread_local`: the pools spawn fresh threads each phase, so thread-local arenas would construct / destruct every phase — per-slot keeps the arena OBJECTS stable (bound once) while their blocks cycle per task ([D-163](../40_decisions.md#d-163)). One slot runs at most one executor at a time — slot ownership is thread isolation.
- **Exact-length bump allocation** (`allocBytes(bytes)`: a resolved `char*` from a byte-bump `alloc`, padding to the next block boundary when the remainder will not fit; output lengths are arithmetic over known input lengths — no in-place growth, an allocation never straddles a block), **rewind marks** (`mark` / `rewind` — the stack-like per-call window; the fixpoint loop's tool), and **per-task `releaseAll`** at `performElem2` exit (RETURNS the blocks to the pool — no retention — and bumps the generation that the scratch string view type asserts against). Freed spans are poisoned with `kArenaPoisonByte` (0xCD, the cold byte). The byte-bump scratch surface lives on the shared bump core (independent of the page tier, so it never collides with `allocPage` containers); a resolved pointer stays valid until its rewind / releaseAll because a scratch arena is never deloaded and never compacted while a task holds it.
- **Cold pool accounting**: blocks come from the pool through `GlobalMemoryManager::acquireBlock` / `releaseBlock`, counted in `blocksInUse` / `grantsSinceBarrier` like any cold grant — the per-task release nets them to zero before every barrier, so the deload SET (a pure function of quiesced logical counts, [I-106](../30_invariants.md#i-106)/[I-107](../30_invariants.md#i-107)) is unchanged and output stays byte-identical; only grant-trigger timing shifts. Acquisition is lazy and uncapped (the pool's own exhaustion assert is the backstop); blocks are released the moment a worker task ends ([I-124](../30_invariants.md#i-124)).
- **`ScratchString`** ([`memory_infra/scratch_string.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/scratch_string.hpp), header-only) — the view type: `char* + length` plus two liveness stamps (arena generation at birth; page-tier used-bytes at birth). Every accessor asserts liveness, so an escaped view is caught at the access site ([I-124](../30_invariants.md#i-124)). Content is immutable after creation — `copyFrom` (alloc + fill) or the fill-then-`wrap` pattern; the empty string carries no arena coupling and is always valid. `toStdString` is the sanctioned boundary escape; the cold-copy escape lands with the ColdString table. **`ScratchScope`** is the RAII per-call window: mark at construction, rewind + poison at destruction; strict stack discipline (the keep-below-the-mark pattern is the sanctioned way to hold an executor-lifetime string across windows).
- **Sealed-page handoff** ([`memory_infra/sealed_pages.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/sealed_pages.hpp) / `.cpp`) — staging-record strings (`FiringRecord` / `StagedAdmissionValue` / `DeferredIntegrationPrep`) are the burst's output, consumed after producing threads finish. Each `SealedPageSet` owns exclusive small slices leased from shared main-pool blocks and retains a private `LbArena` for allocations above the slice capacity. Payload never moves, deloads or survives the existing consumption boundary. `seal` publishes the task's completed records; after the finalize join, `freePages` poisons only that set's used slice bytes and private arena storage, then returns its leases and blocks. Shared backing returns only after the last live slice. `Filling -> Sealed -> Freed` remains asserted; sets remain non-movable and pre-sized per task. `SealedString` remains the borrowed view ([D-164](../40_decisions.md#d-164)). `FiringRecord` carries `SealedString` / `SealedExpressionWithValidity` fields; `markerArgsSorted` is a sorted-unique sealed vector. `proveKernel` releases both kept and discarded outputs after consumption; CE conjectures retain the same independent lifecycle. `applyFiringRecords` sorts by `compareSpans` and materializes at deposit boundaries; `burstDeactivates` materializes only at its probe branches.
- **View-based string operations** ([`memory_infra/str_ops.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/str_ops.hpp), header-only) — `StrSpan` (the non-owning read denominator over scratch / sealed / std::string / cold views; spans inherit their source's lifetime and are never stored) plus the fixed-length operations: `compareSpans` / `equalSpans` (std::string-identical ordering — what keeps decoded-lex walks byte-identical), `hashSpan` (in-house FNV-1a 64, never `std::hash`), `coldKeyHash` (word-at-a-time MurmurHash64A, the byte-key cold maps' probe hash), `copyScratch` (exact-length copy into the scratch arena), `getArgsSpans` / `extractExpression*Span` / `splitByCharSpans` (zero-copy slices into the input), `replaceKeysScratch` / `replaceUSubstringsScratch` (two passes — exact length, then fill). (`concatHot` / `wrapParensHot` were dropped — zero callers.) Twins are proven **byte-identical** to their originals (`ce::getArgs`, `ce::extractExpression*`, `ce::replaceKeysInString` including its greedy-longest-no-retry dispatch and boundary rules, `DefinitionExpansion::replaceUSubstrings` including the erase-and-recheck chain) by the `str_ops` twin-test suite — the pin the scratch migration rests on.
- **Scratch consumers (migration progress)** — `checkLocalEncodedMemoryStatic` (the burst firing check, the heaviest churn site): per-hit window holds the back-replacement pairs (digit keys scratch, values as spans over stable decode refs — the per-hit `std::map<std::string,std::string>` is gone); per-value and per-key windows hold the replace/strip intermediates; argument slicing is zero-copy (`getArgsSpans`); the anchor-prefix test is allocation-free. The slot's arena is RELEASED per executor at `performElem2` exit (blocks back to the pool, generation bumped — no retention). `rplExpr2` stays scratch and is sealed into the record; `std::string` materializes only at the C++17 string-keyed probes (`nameMap.lookup`, `lookupTemplateKey`, `compiledExpressions`). The staging values are sealed end-to-end: `StagedAdmissionValue` (sealed key elements + sorted-unique sealed remaining args), `AdmissionKeyAlgebraRecord`, and `DeferredIntegrationPrep` carry views through the per-burst staging vectors; the drains materialize exactly at their mint points (`mintTemplateKey` / `stagedToIdValue` / `prepareIntegration`), and `performElemPhase2` clears both vectors post-drain — before the post-join sweep frees the pages, so no dangling view ever sits in a `Memory` container and no staging can leak across iterations.
- **Absorb-door consumer (transient campaign Batch T3b)** — `prefixArgumentsWithU` (`compiler/definition_expansion.cpp`) builds its `"u_"+arg` replacement values (NEW bytes, not slices of the input) on the slot's scratch arena, rewound by a `ScratchScope` at return. ## Request-generation scratch — the second per-slot arena

The string-scratch arena above kills transient *string* heap; the transient-statification campaign's Batch T1 kills the transient *int / struct* heap on the phase-2 request-generation read path (`preEvaluateFromEncoded`, `checkLocalEncodedMemoryStatic`, the request generators, `StaticRequestEmitter`). The bounded scratch (`seenSecondary`'s distinct-secondary dedup, `intAllArgs`' arg-membership set) becomes stack arrays; the growable / dedup scratch rides a SECOND per-slot arena — `genScratchArenas` ([`scratch_arena.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/scratch_arena.hpp)), a parallel `ScratchArenaRegistry` instance — kept distinct from the string-scratch `scratchArenas` because the string arena's `ScratchString` liveness tripwire keys off the shared `usedBytes` (byte-bumping it would muddy the tripwire) and its `ScratchScope` rewind would free any page-tier container's pages.

On the gen arena the two `LbArena` tiers run at once, the way a per-LB arena already mixes them: the request generator's DFS frontier (`generateEncodedRequestsStatic::stack`) rides the **byte-bump** tier through `ArenaStack` ([`arena_stack.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/arena_stack.hpp)) — a LIFO whose `popTo` reclaims each popped frame so the footprint tracks the live frontier, not the total pushes; `baseCandidates` and `sortedPairs` ride the **page** tier as `PagedVector`; and the emitted-request dedup `StaticRequestEmitter::seen` is a `ColdHashSet<BytesKeyStore>` keyed by the request's packed bytes (built on the stack). Both arenas are released per worker task at `performElem2`'s single exit, so grants net to zero before each barrier and the work is byte-transparent ([I-130](../30_invariants.md#i-130)). The four name-only `stable_sort` comparators on this path also dropped their per-comparison `nm.decode` heap strings for `decodeView` + `compareSpans`. **Batch T2** then routes the path's last two heap users — the normalized request keys (a former `thread_local` `new int16_t[]` arena) and the `IntEncodedExpr` request-expr copies (a former per-thread `::operator new` arena) — onto this same byte-bump tier (`alloc` + `resolve`), persistent for the task and freed by the same `releaseAll`; they sit below `checkLocalEncodedMemoryStatic`'s per-request `combinedLevels` mark, and the transient grow-DFS keys are dead after `ownerKeyAccepts` (`BaseCandidate` keeps indices), so the `ArenaStack` unwind reclaims them harmlessly.

**Batch T2 — the firing-record staging structs go heap-free.** The deposit side of the same hashburst captured each firing in a `FiringRecord` carrying heap spines — `levels` (`std::set<int>`), `originDeps` / `markerArgsSorted` (`std::vector`), and the `StagedAdmissionValue` / `DeferredIntegrationPrep` arg vectors — five malloc allocations per firing on the hottest path. T2 turns each into a `SealedSpan<T>` ([`sealed_pages.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/sealed_pages.hpp)), the typed-array sibling of `SealedString`: a view over a run bump-allocated onto the same per-task `SealedPageSet` that already holds the record's strings ([D-164](../40_decisions.md#d-164)), so `FiringRecord` is now trivially-copyable POD. The producer (`checkLocalEncodedMemoryStatic`) assembles each run heap-free first — **bounded** runs (`originDeps`, `markerArgsSorted`, `sealedPremises`) in stack buffers, **unbounded** runs (`combinedLevels`, the per-firing level set, `admv.key` / `remainingArgsSorted`) on the gen arena's **byte-bump** tier via `alloc(bytes, alignof(T))` + `resolve`, reclaimed in one `popTo` at the function exit — then seals via `SealedSpan<T>::copyFrom`. The byte-bump runs sit below the function-entry mark, so they never disturb the page-tier `PagedVector`s above (the independent-tier guarantee). (`allocBytes` was once a page-tier fill that would have collided with the page allocator here, so this path used `alloc` directly; `allocBytes` is now itself a resolved byte-bump `alloc`, so the distinction has collapsed — see [D-189](../40_decisions.md#d-189).) The consumer (`applyFiringRecords`) reads the spans for the canonical sort ([I-77](../30_invariants.md#i-77)) and materializes a `std::set<int>` for the level set only at the single-threaded `insertStatement` deposit — the deferred mail/NameMap boundary a later mail batch statifies ([I-131](../30_invariants.md#i-131)).

## ColdStringTable — the cold half of string statification

[`memory_infra/cold_hash_map.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/cold_hash_map.hpp) defines the reusable cold-map family; `ColdStringTable` is now the alias `ColdHashSet<BytesKeyStore>` ([`cold_string_table.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/cold_string_table.hpp) is a 3-line shim — [D-165](../40_decisions.md#d-165), which generalizes the hand-rolled [D-153](../40_decisions.md#d-153)). One table per interner space (NameMap names, NameMap subs, template, value, origin, rule, lb-state — per-interner because `destroyGrid` resets all but `lbStateInterner`): the `BytesKeyStore` policy holds the cold key columns — a `PagedVector<char>` byte pool (append-only, no-straddle so `view` reads one contiguous span) plus a `PagedVector<ColdStringLocation>` id → (byteStart, len) index — and the owning `ColdHashSet` holds the key→id lookup index — DERIVED (never dumped, never a deload input, rebuilt at reload). On this branch ([D-166](../40_decisions.md#d-166)) that index is a **throw-away paged hash** — a `PagedHashIndex` ([`paged_hash_index.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/paged_hash_index.hpp)): open-addressing slots on arena pages with in-place writes, never deloaded, rebuilt on reload — recovering the heap hash's O(1) with no malloc. (The binary branch's fully-cold sorted variant was correct but ~34% slower — [D-167](../40_decisions.md#d-167); the parent keeps a heap hash — [I-117](../30_invariants.md#i-117).) API mirrors the interners: `intern` (find-or-mint, single-threaded — I-83), `lookup` (non-minting, burst-safe), `view` (zero-copy `StrSpan`, resident-only — the residency discipline of element refs), `decodeString` (boundary materialization), `copyFrom` (CE clone), `resetToFresh` (`destroyGrid`). Deload = two GLDL tags per table: lengths (int32, id order) + concatenated bytes — pure content; `bulkLoad` reproduces every location and id exactly. **Wired**: the `LengthsView` / `BytesView` facets satisfy the generic deload visitor unchanged (the lengths facet owns the whole-table lifecycle forwards — clear / release — the bytes facet's are defined no-ops; reload joins the two tags through a staged-lengths handshake; the bytes tag's tail windows are byte-indexed and assert string-boundary alignment). **Migrated interner spaces: all seven per-LB ones** — `TemplateInterner` (tags 4–5), the four `ValueInterner` instances: value (6–7), origin (8–9), rule (10–11), lb-state (12–13), and `NameMap` (names 14–15, subs 16–17). Every façade is stateless (bound in `Memory`'s constructor; `decode` returns an owned copy — every pre-existing call site already copied, per the I-3 discipline; `decodeView` is the zero-copy span for ordering and burst reads). The ordering primitives `valueIdLess` / `valueIdVectorLess` — which sit under every decoded-order container comparator — compare spans, zero allocations. `destroyGrid` resets template/value/origin/rule and the NameMap (`resetToFresh` plus `initMetadata` — never reassignment, it would sever the binding) and deliberately skips the lb-state space, whose table keeps its arena blocks so `expandedImplications` decodes stay valid across grids. The burst's firing path decodes the rule space exclusively through views (the sort comparator, the replace inputs, the origin sealing, the remaining-args spans).

**NameMap on the cold tables.** The validity-name interner's two string tables live on the LB's pages, and `MAIN_ID == 1` is "main". The NameMap-cold campaign (, [D-138](../40_decisions.md#d-138)) then made the int↔string mapping **direct**: "main" is lazily interned as cold-table id 1 on the first encode, so a public id equals its cold-table id (no `+1` offset); the eternal-root branches in `lookup` / `decode` / `decodeView` cover the window before that intern (`mainName` is the one static heap string). The id-form metadata moved off the heap onto a flat paged parent-pointer forest (`validityNodes`, see below); `pairMap` was dropped (`verdict` derives by walking it). Canonical-name composition (`encodePush` = parent canonical + separator + payload) and `decode` materialize; burst probes use the non-minting `lookup(StrSpan)` overload. The former `stringAncestorsOf` string-set member is deleted — `strictAncestorNames` decodes `ancestorsOf` on demand (sorted, byte-identical to the old set iteration), and `isStrictAncestor` answers through the derived `verdict` (`ancestorsOf` membership) without decoding.

**Memory members on NameMap ids.** `recursionHypothesisId` and `contradictionTheoremId` use zero for the defined unset state and reset with their NameMap. No persistent mail-permission sets remain. Parked source blobs append one int32 integration-depth assignment; internal disintegration signals use a 64-bit value whose low word retains flags and algebraic generation and whose high word retains assigned depth plus one (zero means no replay assignment). These existing enrolled records survive clone and both deload formats.

## Cold-map family — one reusable class (`HashMap<KeyStore, ValueStore>`); set / map / multimap / set-map are aliases

[`memory_infra/cold_hash_map.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/cold_hash_map.hpp) ([D-165](../40_decisions.md#d-165), [D-207](../40_decisions.md#d-207), [I-117](../30_invariants.md#i-117)). The `ColdStringTable` pattern — a derived lookup index (rebuilt on reload) over key/value DATA that is cold and paged (deload-persisted) — is one reusable class `HashMap<KeyStore, ValueStore>` (the engine — `mint` / `lookup` / `decode`, the throw-away index, the lifecycle — lives once), so the remaining per-LB heap maps (`admissionMap`, `rejectedMap`, the origin maps, …) can migrate onto a single skeleton instead of N hand-rolled classes. Two **key-store policies**: `BytesKeyStore` (variable-length byte keys — a `PagedVector<char>` pool + a `PagedVector<ColdStringLocation>` index, two deload tags) and `PodKeyStore<K>` (a fixed trivially-copyable key in one flat `PagedVector<K>`, one tag; a `has_unique_object_representations` static-assert rejects padded keys whose indeterminate bytes would break the hash/equality/deload). Each `ColdStringLocation` is one 8-byte record: the byte location, a 14-bit length (a key never leaves its page) and an 18-bit tag of the key's 64-bit `coldKeyHash` digest ([D-423](../40_decisions.md#d-423), [D-466](../40_decisions.md#d-466)). Lookup computes the probe digest once and rejects collision candidates by tag before touching the byte pool; a matching tag still requires the full length and byte comparison. Index rebuilds recompute each stored key's digest from its bytes to place it (`BytesKeyStore::hashStored`); a fresh mint takes the bucket its own miss probe found. The tag remains static page-backed data, not heap state. It is derived rather than canonical: the two-tag deload image remains lengths + logical bytes, `copyFrom` copies the tag, and reload recomputes it from those canonical bytes. A second axis is the **value-store policy** — the value column. Its four instantiations are exposed as **aliases** of the one `HashMap<KeyStore, ValueStore>` class (`ColdHashSet` = `EmptyValueStore`, `ColdHashMap` = `SingleValueStore<V>`, `ColdMultiMap` = `CsrValueStore<V>`, `ColdSetMap` = `SetValueStore<V>`); the value store is a private empty-base, so a set's `EmptyValueStore` is elided (empty-base optimization — `[[no_unique_address]]` is a no-op under C++17/MSVC) and a set's layout stays byte-identical to the hand-rolled one. Each value store exposes a uniform contract (`clearValues` / `releaseValues` / `copyValuesFrom` / `valuesLiveBytes` + `kTagCount`) the engine calls branch-free. The four forms:

- **`ColdHashSet<KeyStore>`** — the interner (cold keys + dense positional ids + the lookup index — a heap hash on the parent, a **throw-away paged hash** (`PagedHashIndex`) here, [D-166](../40_decisions.md#d-166)). `PagedHashIndex`'s bucket array two-levels its page directory exactly like `PagedVector`'s and, like it, hard-asserts on directory overflow — replacing a former unchecked write that silently ran off the single directory page ([D-144](../40_decisions.md#d-144)). `ColdStringTable == ColdHashSet<BytesKeyStore>`.
- **`ColdHashMap<KeyStore, V>`** — a key set + a parallel cold `PagedVector<V>` value column (`values_[id-1]`). `insert` is **set-once** (asserts a new key, never a silent overwrite); the separate reviewed door `setValueAt(id, v)` does the in-place value update (Rule 8/19; → `PagedVector::setAt`, which marks the aggregate `Restructured`), its first consumer `upsertStatementKey`'s flag-bit OR. `find` returns `nullptr` on a miss (a defined query result, the bivalent twin of `lookup == 0`).
- **`ColdMultiMap<KeyStore, V>`** — key → an ordered value run in **CSR** form (a `PagedVector<int32_t>` run-start index + a flat `PagedVector<V>` value column). The run length is DERIVED (next key's start, or the value total for the last key), since the const-access `PagedVector` cannot bump a stored length in place. **Append-to-tail only**: `appendToTail` asserts the key is the current last or brand-new (a pure append); interior-key insert (an O(N) column shift) is deferred to a real consumer.
- **`ColdSetMap<KeyStore, V>`** ([D-168](../40_decisions.md#d-168), [I-118](../30_invariants.md#i-118)) — key → a **sorted-unique SET** of values: the same CSR layout as `ColdMultiMap` (`SetValueStore<V>`, two value tags) but the run is kept SORTED + DEDUPED by the set surface. `insertSorted(k, v, cmp)` binary-searches the run, returns on a `cmp`-equal hit (dedup), else splices `v` at its sorted position (`PagedVector::insertAt`, the interior shift `ColdMultiMap` forbids) and bumps every later key's run start; `assignSet(k, vals, m)` replaces a key's whole run (in place when the size is unchanged); `setContains` is a linear membership probe; `eraseSet` / `eraseSetIf` run a run-aware forward compaction (each survivor's key + run start + whole run slide to the front). The comparator is PASSED PER CALL (defaulted `std::less<V>`; a `ValueInterner`-bound decoded-id comparator for `orBookkeeping`), never stored — no interner-lifetime coupling. The Batch-2 substrate for the int→set maps; distinct from `ColdMultiMap` by type so the bag's `appendToTail` and the set's `insertSorted` never mix.
- **`ColdBlobMap<KeyStore>`** ([D-169](../40_decisions.md#d-169), [D-208](../40_decisions.md#d-208), [I-98](../30_invariants.md#i-98)) — key → an ordered RUN of variable-length byte BLOBS (`BlobCsrValueStore`), each blob one record's canonical serialization: the **record value store** no single trivially-copyable `V` could hold (a multi-field record — Batch 3's `EquivalenceClass`, the Batch-4 `HashMemory` record-set values). Record-AGNOSTIC: a per-record call-site codec produces / consumes each blob; the store only moves bytes. A two-level CSR — `runStarts_` (key → first blob index), `blobStarts_` (blob → byte offset), dense `blobPool_` — every boundary DERIVED (the blob length from the next `blobStart`, like `runLen` from `runStarts`); four deload tags with a POD key. `assignRun` handles a contiguous whole-run replacement; `assignRunGenerated` handles a replayable segmented run wider than one arena block. Both splice the byte + blob columns once each through `PagedVector::replaceRange` / `replaceRangeGenerated`, so every surviving tail moves once and the dense output is identical. `eraseBlobIf` remains the run-aware compaction door. Blobs may straddle pages (read through `contiguousRun`), so the pool is dense and deloads via `appendSpanBytes` with no staging handshake. The canonical-bytes contract lives in the CODEC (sort every hash-backed field before emit), not the store.

**Mutation beyond append ([D-170](../40_decisions.md#d-170), [I-119](../30_invariants.md#i-119)).** The POD-key AND byte-key set / single-value map support per-key removal: `erase(key)` and the bulk `eraseIf(pred)` compact in one forward pass — survivors slide to the front of the key + value columns (`moveKeyTo` / `moveValue` → `PagedVector::setAt`; `moveKeyTo` is position-based, so a byte key slides only its location entry, the erased key's bytes left as a hole in the append-only byte pool the copying compaction reclaims), the dead tail is `truncate`d, and the throw-away index is rebuilt once — preserving survivor order so the deload stays canonical (O(count), not the per-element-shift O(removed × count)). They — and the in-place `setValueAt` above — mark the aggregate `Restructured`, so a mutated container is never tail-delta'd (which would silently drop the change). Erase is the `Memory::wipeSubtree` driver for the int-keyed-map migration; byte-key erase joined on Batch 2 (the flattened `eqClassSttmntIndexMapMap`). `ColdMultiMap` erase stays deferred (a CSR bag has no per-key `moveValue` — a compile error); the CSR set form `ColdSetMap` erases run-aware via `eraseSetIf`. The new storage primitives are `PagedVector::setAt` (in-place write), `insertAt` (shift-right splice — the set form's interior insert), and `truncate` (tail-drop), all reviewed (Rule 8/19). A sibling, `PagedVector::setAtRelaxed` (with `SingleValueStore` / `HashMap` / `TypedCold` `setValueAtRelaxed` forwarders), is `setAt` WITHOUT the dirty escalation: it writes only the element slot, so concurrent calls on DISJOINT indices are race-free. Its ONLY sanctioned use is a container on a NEVER-DELOADED pool whose dirty state is meaningless — the pull-model mail cursor, advanced disjointly by each recipient's worker in the parallel phase-1 pull where touching the shared dirty flag would be a data race ([`03_mail_system.md`](03_mail_system.md)). On a deloadable container it would silently skip the rewrite the change needs.

Deload-tag accounting per form follows the key store's `kTagCount` plus the value/run columns (bytes-set 2; pod-set 1; `+1` per value column; `+1` for the multimap / set-map run-start index) — the generic `lb_deload` visitor consumes each form's facets with no structural change: the byte-key set's `LengthsView` / `BytesView`, the POD-key forms' self-contained `KeysView` (1 tag) + a map's `ValuesView` (1 tag), and a CSR map's `KeysView` + `RunStartsView` + `RunValuesView` (3 tags), the key tag preceding the run-start tag preceding the value tag so reload loads keys (and rebuilds the index) before the parallel columns. **Status:** `ColdHashSet` and `ColdHashMap` are live in `LbMemory` — the seven interners + NameMap as byte-key sets, plus Batch 1's POD-key int sets + maps (tags 19–34); `ColdSetMap` (with the `RunStartsView` / `RunValuesView` facets that first teach the deload visitor the CSR shape) is built + unit-tested (`tests/test_cold_hash_map.cpp`) and **wired into `LbMemory`** for the int→set maps: Batch 2 migrated the set-/nested-valued maps: `intStatementLevelsMap` (tags 38–40), `orBookkeeping` (tags 41–43, the disjunct run kept in decoded order by a per-call `DecodedIdLess`), and the nested `eqClassSttmntIndexMapMap` (flattened to a byte-key `ColdHashMap<BytesKeyStore, int>`, tags 44–46); the fourth, `intToBeProved` (tags 35–37), later moved to the never-deloaded persistent pool as a direct `Memory` member (tags retired — [I-108](../30_invariants.md#i-108)). Mail is excluded from the migration. **Batch 3** adds the record value store: `ColdBlobMap` (with the `BlobStartsView` / `BlobPoolView` facets) is built + unit-tested and **wired into `LbMemory`** for `equivalenceClassesMap` (tags 47–50 — a validity id → its class list, one canonical `EquivalenceClass` blob per class); the derived `changedClassesThisStep` (tag 655, dischargeable) and `eqClassNameCaches` (tag 705, survives discharge) later moved onto the cold DELOADABLE arena, enrolled in `visitContainers` (`I-125`, retiring [I-120](../30_invariants.md#i-120)'s non-deload-hot pattern). **Batch 5** migrates the LB's standalone origin map `Memory::exprOriginMap` onto `ColdBlobMap` (`TypedColdBlobMap<int64_t, IdOrigin>`, tags 451–454 — appended AFTER the HashMemory band so the enumeration stays ascending) with `Record = IdOrigin` (one history line = one variable-length blob — `OriginTag` + packed dependency keys, byte-identical to `serializeEquivalenceClass`'s per-line stream); it is the LAST standalone heap origin map (the equi-class `equalityOriginMap` already rides the `equivalenceClassesMap` blob since Batch 3), survives discharge (the chapter export reads origin history on discharged LBs) and survives `wipeSubtree` ([I-44](../30_invariants.md#i-44)), and is reached through cold twins of the `addOriginId` / `addOriginEncoded` / `decodeOriginMapSorted` helpers (overload-routed by the map type); the equi-class→body merge becomes a sorted in-place RMW so a class-only key is minted deterministically (canonical deload). The append-only fixed-`V` bag `ColdMultiMap` is NOT the substrate — the origin value is a two-level variable-length record, so the blob map is. Mail stays string across the boundary ([I-121](../30_invariants.md#i-121)). **Index location (this branch):** the key→id index — a heap open-addressing hash on the parent — is here a **throw-away paged hash** (`PagedHashIndex`: open-addressing slots on arena pages, in-place writes, never deloaded, rebuilt on reload), so every cold map leaves the heap entirely while keeping O(1) lookup ([D-166](../40_decisions.md#d-166); the binary branch's fully-cold sorted variant was correct but ~34% slower — [D-167](../40_decisions.md#d-167)); keys / values / ids / deload stay byte-identical.

**Routing mail split by lifetime.** `Memory::mailIn` remains `RoutingColdMail` on a dedicated per-LB arena from `mailMemory`: phase 1 claim/reloads first, then pulls and absorbs the inbox, and `clear` returns its blocks immediately. `Memory::mailOut` is `DeloadableMailOut` inside `LbMemory`, tag band 755..804: a dedicated string table plus statement and origin columns, all on `lbMemory.manager`. Its write doors raise `mailOutPending`; the commit sweep reads that shell bit, claim/reloads only pending LBs, serializes through the private interner, clears all three stores, and releases the claim. **Internal mail onto the cold deloadable path.** The two internal-mail channels are the cold counterpart of the routing move. ## ReverseArgsIndex — a derived reverse membership side-index for a cold blob map

[`memory_infra/reverse_args_index.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/reverse_args_index.hpp) ([D-199](../40_decisions.md), [I-154](../30_invariants.md)). ## ValidityNode forest — the paged NameMap metadata

The NameMap validity metadata is a flat per-id parent-pointer forest, not a jagged container: one `ValidityNode {int16 parentId; int16 ownSubId}` per validity id, held in a single `PagedVector<ValidityNode> validityNodes` on the LB arena (`lb_memory.hpp`; [D-138](../40_decisions.md#d-138), [I-104](../30_invariants.md#i-104)). `parentId == 0` marks a root (`"main"` and any flat `encode` root; position == validity id, id 0 unused, id 1 "main"); a non-root carries its own `_boundary_` payload sub-id. `NameMap` holds the vector as a façade pointer, bound in `Memory`'s constructor.

The `stackOfValidity` / `ancestorsOf` "lists" are DERIVED views: a query walks the `parentId` chain from a scope up to its root (`ancContains` / `ancLen` / `ancAt` / `stackLen` / `stackBack` / `pairCount`). `encodePush` is O(1) — it stores one `{parentId, ownSubId}`, never copies a parent list. The forest is ~7× leaner than the earlier jagged CSR (4 B/id vs ~30), O(1) to extend, and answers `verdict` / `comparable` in the same O(scope-depth) walk — the RT-best of the layouts considered (a smaller cold footprint helps cache + deload IO, the only things the burst pays for here, while the kernel-phase comparisons that call `verdict` stay fast). Being flat and trivially copyable it deloads as ONE tag (`ValidityNodes`, visited DIRECTLY like the statement vectors — no facets, no lengths/entries split), a raw id-order int stream byte-identical across runs and hosts ([I-103](../30_invariants.md#i-103)).

**Lazy seeding + eternal root** ([I-105](../30_invariants.md#i-105)). A freshly bound `NameMap` holds zero nodes — a transient `Memory` consumes no pool blocks. `seedIfEmpty` (top of `encode` / `encodePush`) appends the slot-0 sentinel + "main" nodes on first touch (and `internMain`s "main" as cold-table id 1). Reads of `MAIN_ID` before that resolve to the eternal-root values (`{main}` ancestors, empty stack) via accessor fallbacks, byte-identical to the seeded answer — so the lazy scheme is observationally identical to eager seeding. The forest **survives discharge**: an emptied container would read as unseeded and assert on a non-root id, and the post-prove readers still resolve validity ids into it. The element accessors retire the old `stackOf` reference return — no reference into paged storage escapes ([I-3](../30_invariants.md#i-3)).

## First migrated container — `intEncodedStatements`

`Memory` holds `LbMemory lbMemory` plus a **reference alias** `intEncodedStatements` into it, so the registry's many access sites — including the Rule-14 sacred hashburst dump, every `push_back` writer, and the size/index readers — keep their `body.intEncodedStatements` spelling unchanged. The alias is pure (no separate state) and makes `Memory` non-whole-assignable by design (teardown swaps individual members; the statified registry's teardown idiom is `release`, replacing swap-with-empty at the root reset and the CE batch release). Iterator-form erase sites became index-form (`wipeSubtree`, the two erase-rows lambdas); the one range-for became an index loop; `cloneFactsTemplate`'s member assign and the scope-teardown rebuild assign use the shared lists' full-record copy-assignment interface. `IntStmtView` reads shared statement lists and independent scratch vectors through one indexed interface. The unit-test harness initializes the process-wide pool with the `ProverParameters` default pair, which equals every batch config's values, so `Prover`-constructing tests hit the idempotent re-init path. Capacity intuition changes with the switch: see [G-52](../50_gotchas.md#g-52).

## Weaknesses

- **Resolved — large live containers can outgrow two-level directory coverage.** At 2 KiB pages the two-level shape covers 512 MiB of data pages, which a live OR matching index can reach before pool exhaustion. `PagedVector` and `PagedHashIndex` now add a third level only past that boundary. Page and pool sizes remain unchanged; splitting execution work does not itself partition these per-block indexes. Independent signed size bounds remain enforced. Direct small-page tests cover full third-level coverage, promotions, demotions, retained-page reuse, exact content, reclamation and canonical byte identity; subprocess cases check directory and element-count overflow. See [I-276](../30_invariants.md#i-276).

- **Resolved — the vid ratchet (`pageTable_` growing monotonically under churn) is closed by free-vid reuse ([D-228](../40_decisions.md#d-228), maintainer-approved 2026-07-14).** Historically `LbArena::allocPage` always bound the NEXT tail vid and interior `freePage`s left permanent null holes, so cold-container RMW churn ratcheted the vid space without bound: the FTA rung-2 run crossed 524K vids in one LB arena holding single-digit block counts, overflowing `PtrDirectory`'s spilled root at cap 16 and again outgrowing the raised cap 128 (~2.8× growth per burst). Now `freePage` pushes the freed vid onto a per-arena intrusive LIFO — the dead `pageTable_` slot itself stores the tagged next-free-vid link (low bit 1, so it can never alias a page-aligned pointer), no side container, no heap — and `allocPage` pops it before minting a fresh tail vid, so the table is bounded by the LIVE-page high water. Reuse is deterministic (same allocation/free sequence, same vids); on a raw reload the chain is DERIVED canonically from the live-vid bitmap (ascending pop order — the pre-dump LIFO history is deliberately not serialized; vid values never reach canonical proof bytes, I-103, and deload points are themselves deterministic, I-106). Compaction (`reshuffle`) moves only physical bindings, never vid values, so the chain survives it untouched. `kArenaDirRootCap` stays at 128 — now sizing ~4.2M LIVE pages (33 GiB of 8 KiB pages per arena), pure headroom. `LbArena::assertInvariants` proves the chain shape (length == dead-slot count, in-range nodes, termination) at every coarse seam.
- **Suspected fragility — ScratchString use-after-rewind detection has a refill blind spot.** A view that crosses a rewind below its birth asserts while its span is still poisoned, but once later allocations refill past its birth position the generation + used-bytes checks can no longer tell it from a live view (no per-allocation metadata, by design). The contract is stack discipline — copy out before the window closes; the checks are the tripwire, not the license. If a silent case ever surfaces, the candidate hardening is a two-tier arena split (per-call scratch with rewind-equals-invalidation vs executor-lifetime burst storage).
- **Pool sizing is telemetry-driven now.** The default was raised 2 GiB → 4 GiB (cold string tables past `IncubatorPeano1`'s old bound), then 4 GiB → 8 GiB for working-set-pager headroom. The user-directed configuration returns the main pool to **4 GiB / 16384 blocks** so the heavy batches run under real pager pressure ([D-209](../40_decisions.md#d-209)). The historical 2026-07-10 seven-batch Windows measurement under the former 8 GiB cap recorded **23325 blocks / 5831.25 MiB** for `IncubatorPeano1` and **18564 blocks / 4641.00 MiB** for `IncubatorGauss1`; these figures explain why the 4 GiB configuration depends on deload/reload rather than fitting the whole peak resident set. An undersized pool asserts loudly (by design); an oversized one costs only address space, since blocks are committed when first carved ([D-418](../40_decisions.md#d-418)). The per-run `memory_<postfix>.log` is the authoritative sizing artifact for later comparisons.
- **Known & tracked — the chapter export reloads LBs on demand and MUST release them per chapter** ([G-53](../50_gotchas.md#g-53)). `buildStack` / the export driver call `ensureLoadedForRead` on every LB across the proof-graph walk; with `encodedMap` now on the arena each reloaded LB drags back real blocks. Without release the resident set grows monotonically across the walk to pool exhaustion — which surfaced as `IncubatorPeano1`'s export hitting the pool bound (NOT a prover footprint, and NOT a reason to raise `static_pool_bytes`). `generateRawProofGraph` now releases each theorem's reloaded LBs (`releaseStaticBlocksDispatch` — kind-routed per the extent-file section — via the `g_exportReloadSink` that `Memory::reloadFromImage` populates only during the export) at the end of its chapter; the on-disk image stays, so a later theorem revisiting an LB reloads it on demand. Measured: the export holds a flat ~11.9k blocks instead of climbing. The `encodedMap` RMW insert no longer round-trips the whole run: `TypedColdBlobMap::appendRecord` serializes the one new record and splices it at the key's run-end via `HashMap::appendBlobToRun` (a `replaceRun(b0+oldCount, 0, …)` insert plus the later-key run-start rebase), replacing the former `lookup`+`recordsAt`+`push_back`+`assignRun` whole-run decode+re-encode (O(run) per insert, ~O(run²) per key). The run content is byte-identical — the new record lands at the same run-end — so the deload bytes and proof are unchanged; the residual per-insert cost is the O(blob-tail) CSR shift, now a BULK page-span `memmove` (`PagedVector::blockMove`, one `memmove` per page-bounded span — not the former per-byte `operator[]`+`writeSlot` resolve loop), and O(1) when the grown key owns the pool tail.
- **Resolved — `HashMemory` folded INTO `LbMemory` (the Part-C endgame, [D-147](../40_decisions.md#d-147)).** All four instances (`overallHashMemory` / `localHashMemory` / `localHashMemoryDelta` / `workingMemory`) are now `LbMemory` members, declared after `manager` so they destruct before the arena their cold containers ride. `Memory` keeps reference aliases (`HashMemory& overallHashMemory = lbMemory.overallHashMemory`, the `intEncodedStatements`/`equivalenceClassesMap` alias pattern) so the thousands of `body.overallHashMemory…` call sites are unchanged. `LbMemory::visitContainers` — the single enumeration the deload dump / load / **release** drive — now reaches them: after its own tags 0..50 it calls each instance's `HashMemory::visitContainers(base, …)` at `kOverallHashMemoryDeloadBase` (51) / `kLocalHashMemoryDeloadBase` (151) / `kLocalHashMemoryDeltaDeloadBase` (251) / `kWorkingMemoryDeloadBase` (351), bridging `HashMemory`'s `uint32` `base+offset` tag into a `ContainerTag` (cast) so the deload directory records 51..450 **byte-identically** to the former extra-column path. Within each 100-tag block `HashMemory::visitContainers` emits `encodedMap` `base+0..4`, the four owner-set maps `base+5..24` ([D-140](../40_decisions.md#d-140)), the algebra admission/rejection subsystem `base+25..37` ([D-172](../40_decisions.md#d-172)), the integration twins `base+38..47`, the residual flat sets `base+48..50` + `originals` `base+51..52` + `remainingArgsNormalizedEncodedMap` `base+53..57` ([D-173](../40_decisions.md#d-173)). All four instances **survive discharge** (`LbMemory::survivesDischarge` returns true for tags 51..450): a discharged LB keeps its hash engine resident so the post-prove chapter export reads its origin history, then the pending drain dumps the full image (matching the pre-fold behaviour where discharge never emptied `HashMemory`); `HashMemory::liveBytes` now joins `LbMemory::liveBytes` (the reshuffle gate, content-invisible). The transient pair (`localHashMemoryDelta` / `workingMemory`) is still emptied per burst by `resetToFresh`, never by deload. The fold retired the three manual hooks the out-of-`LbMemory` placement forced: `buildHashMemoryDeloadColumns` + the `extraDump`/`extraLoad` lists; the manual `HashMemory::visitContainers(base)` release in `Memory::releaseStaticBlocks`; and the explicit `~Memory` that released the cold containers before the arena died (the `freePage`-on-dead-arena hazard is gone — natural reverse-declaration destruction runs `HashMemory` before `manager`). `HashMemory` and its deload-base constants live in [`memory_infra/hash_memory.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/hash_memory.hpp) (the blob-map record value types forward-declared; defined with their codecs in `memory.hpp`). The `lb_deload` `extraColumns` parameter survives as a defaulted, now-unused general extension point.
- **Known & tracked — the Batch-2 set maps cost ~28% runtime.** The four set-/nested-valued maps on `ColdSetMap` / the byte-key `ColdHashMap` (intToBeProved, intStatementLevelsMap, orBookkeeping, eqClassSttmntIndexMapMap) ran the full pipeline ~28% slower at the Batch-2 gate (~1303 s vs ~1019 s baseline) — the interior-insert column shift + per-write canonicalization the cold set form pays that the heap maps did not. Proof content is byte-identical (131018 verifier checks, 0 failures; two runs identical). Accepted deliberately — memory, not runtime, is what gates FTA ([D-168](../40_decisions.md#d-168)). Optimizing the hot insert path (or flattening the heaviest container to a packed-pair `ColdHashSet`) is the open lever if runtime later binds. (`intToBeProved` has since moved to the persistent pool — [D-149](../40_decisions.md#d-149) — leaving three of the four on the cold set form.)
- **Generated blob-run replacement closes the former prefix-start heap violation.** `BlobCsrValueStore::replaceRun` now routes even contiguous sources through `replaceRunGenerated`: the replayable record emitter fills `blobPool_` and then generates `blobStarts_` prefix offsets directly into paged destinations. No `std::vector<int32_t> newStarts` remains on the live `standardProcessing` tree, restoring the I-138 0%-heap contract while preserving the same dense CSR bytes.
- **Not exercised by tests — multi-threaded grant traffic.** Unit tests exercise grant/release single-threaded; the mutex path under real parallel sweeps is only exercised by full pipeline runs.
- **In progress — `LbArena` page-tier bookkeeping lifted off the heap (re-opens D-174).** The MPU 0.1 close-out (2026-06-27, D-174) left `LbArena`'s block/page lists on the heap as an O(blocks) carve-out, recorded as a future option declined "until the live architecture proves it needs the saving." The maintainer re-opened it — the deferral was for prover instability (since fixed), not a design flaw. The lift targets only what lives INSIDE the LB (the per-LB `LbArena` bookkeeping), via a small-buffer **`PtrDirectory<kInline>`** ([`ptr_directory.hpp`](../../../GL_Quick_VS/GL_Quick/src/memory_infra/ptr_directory.hpp)): the "page the page tables" technique with a per-directory inline buffer, so the numerous SMALL arenas (scratch / routing-mail / a typical `persistentArena`) cost ZERO pool block while a large page table spills to wired-root pool blocks (strict two levels, assert-not-recurse). **Done:** the page table (`pageTable_` → `PtrDirectory<128>`), the page free-list (`freePages_` → an intrusive LIFO, the next-free link in each free page's LAST `sizeof(char*)` bytes so the poison still covers offset 0), and the byte-bump / carved-block lists (`blocks_` / `pageBlocks_` → `PtrDirectory<16>`). **Compaction scratch:** steward and worker compaction use separate scratch arenas on the LB-body pool; see `steward.hpp`, `compactIfFragmented` and `stewardScratch_`. **OUT of scope (maintainer):** `GlobalMemoryManager`'s `granted_` / `recycled_` (one process-wide instance, the root that hands out the pool) stay on the heap; `LbStore::blocks_` (the slab holding LB shells, not inside one LB) is left for later. Byte-transparent: arena bookkeeping is never serialized (I-107), so deload bytes, theorems, and verifier are unchanged; the only new observable is a few more pool blocks for the rare large page table (telemetry only, I-106). Decision: [`D-188`](../40_decisions.md). (The per-container spine — `PagedVector`'s directory — already lived in the arena, not the heap.)

## Bounded host projection lifetime

The CUDA device still receives one complete immutable image per unchanged logical chunk. Host construction uses consecutive whole-block windows sized from measured columns, targeting `kPhase2HostWindowTargetBytes` (32 MiB, shared by the executor and the host planner; [D-491](../40_decisions.md#d-491)) per window while permitting a single larger block's exact requirement; at most two windows are alive. Parallel shards share each window's backing storage. Once rebased columns are uploaded, only block descriptors, source statement ordinals and name/rule lookup records/bytes remain for scheduling and sealing. One window may upload while the next is built; the upload thread empties a window's slot as soon as its upload and sealing copy finish, so a finished window never stays alive beside the next one. No main-pool sizing, device budget, proof policy or semantic work changes. Source: proof/phase2_executor.cpp, Phase2Executor::execute; gpu/phase2_host_plan.hpp, kPhase2HostWindowTargetBytes; gpu/phase2_projection.hpp, Phase2ProjectionArena::SealingOnly; gpu/phase2_cuda.cu, appendStreamedUpload and Phase2WindowUploader::work.

In the earlier isolated single-window bounded-upload experiment, two unchanged-build full-profile runs lower the largest process working-set peak from 5886.0 to 5293.0 / 5292.8 MiB and IncubatorGauss1 from 5103.2 to 3972.1 / 3978.5 MiB. The projection census counts the largest live window plus retained sealing data: 1255.3 -> 427.2 MiB in IncubatorPeano1 and 1605.7 -> 321.6 MiB in IncubatorGauss1. Native prover time increases 4.48 / 4.28 percent; smaller one-window projections can hold more host bytes briefly because the retained copy overlaps construction. The summed chunk host total is an accounting upper bound when construction and sealing peak at different times. The [experiment ledger](../../../ledger/fta_f3_memory4_proposal1_ledger.md) preserves both exact-artifact validations and this measured tradeoff.


## Shared canonical dependency edges

`CanonicalUseIndex` keeps each exact `(token, record)` pair once in `CanonicalDependencyEdges`, as one recyclable 24-byte slot: a 16-byte member-walk element (member next link, insertion revision, member and record identifiers) and an 8-byte link element (member previous link, record next link). The identifiers point into the store's own member and record maps, which keep the exact 64-bit keys and each key's newest slot. The record map is also the index's live-record registry: its value is the newest slot, the token-free live state or the retired state. No pair hash index exists; an exact pair is found on its record's short newest-first list. Both traversals retain newest-first insertion order. Duplicate insertion changes nothing; deletion unlinks both lists before recycling a slot. A scope wipe compacts both maps and rewrites each live slot's identifiers by walking every surviving list, without moving slots, links or revisions. The token revisions and observation maps remain separate.

The store stays on the owning logic block's arena and is derived, never a canonical deload input; its maps and columns escalate the owning index's raw-change flag. Raw eviction retains its slots and links; canonical release clears them and the normal source synchronization rebuilds them. Scope cleanup preserves surviving insertion revisions and ordered selection. See [D-435](../40_decisions.md#d-435), [D-487](../40_decisions.md#d-487) and [I-279](../30_invariants.md#i-279). Source: `memory_infra/canonical_dependency_edges.hpp`, `CanonicalDependencyEdges`; `memory_infra/canonical_use_index.hpp`, `CanonicalUseIndex`.

In the isolated shared-edge experiment on the fixed FTA F3 full GPU profile, two unchanged-build runs reduce the largest process working-set peak from 5886.0 MiB to 5825.7 / 5825.8 MiB. Peano reduces 2413.6 to 2203.4 / 2201.4 MiB, Gauss 1753.0 to 1629.3 / 1628.8 MiB; FTA itself increases 3654.9 to 3679.8 / 3668.3 MiB. Summed native time changes +0.40 / -0.35 percent, with individual batch regressions retained in the [experiment ledger](../../../ledger/fta_f3_memory4_proposal3_ledger.md). These process peaks are independent and must not be added or equated with the per-edge payload saving.

### Combined accepted memory measurement

On the fixed full GPU profile, bounded projection uploads, phase-3 page compaction and shared canonical edges together reduce the largest process working-set peak from 5886.0 to 5246.7 MiB (5.12 GiB), saving 639.3 MiB (10.86 percent). Native prover time is 525.43895 seconds versus 483.98208 (+8.57 percent). The completed combined run matches all 3831 main reference artifacts and the entire 3791-file proof/theorem inventory byte for byte. These are combined measurements; the isolated figures above describe the individual experiments. See the [integration ledger](../../../ledger/fta_f3_memory4_integration.md).


## Exclusive sealed slices share backing blocks

Small sealed allocations use exclusive slices leased from ordinary main-pool blocks. Sixteen aligned slices fit in a block, with in-block allocation metadata. A set owns its chain, payload and poisoning range; backing storage returns only after the last live slice. Allocations above the slice capacity keep the existing private byte arena and full-block contiguous limit. The sealed allocator has a separate mutex, always acquired before the ordinary pool mutex. Logical record order, lifecycle and content do not depend on block or slice addresses. Source: `global_memory_manager.cpp`, `GlobalMemoryManager::acquireSealedSlice` / `releaseSealedSlice`; `sealed_pages.cpp`, `SealedPageSet::alloc` / `freePages`.

See D-439 and I-281.

## Share immutable rule value bytes across independent maps

The four hash memories bind encoded rules, normalized subkey records, whole-key owners and remaining-argument/copy owner records to the block's immutable shared byte dictionary. Each map keeps its own membership, ordered runs, owners and canonical offsets. A four-byte positive handle names page-contained shared bytes; an opted-in record store uses a negative handle for a larger private paged record. Normalized-key value stores retain their original page-contained contract. Large private records are compacted at the same quiescent shared-pool collection seam. Full canonical streams reconstruct identical bytes; raw images retain the private columns and handles. Source: `cold_hash_map.hpp`, `BlobCsrValueStore::internSharedBlob`, `blobChunk`, `compactOversized`; `hash_memory.hpp`, `HashMemory::bindSharedBytes`. The experiment measures total dictionary/reference overhead as well as removed copies; tiny records need not yield a net saving.

See D-440 and I-282.

## Shared immutable expression records

`shared_expression_list.hpp`, `SharedExpressionStore` and `SharedExpressionList`, give each logic block one exact-byte record store and four independent ordered reference lists. A 32-bit identifier addresses an immutable `IntEncodedExpr`; full identity includes scope, flags and all argument fields. Reference counts preserve list lifetimes independently, freed slots are reused, and the last release frees the entire store. Partial free slots remain allocated and count against measured savings. The derived hash table resolves collisions by full-record comparison.

The main, local, newly-local and external lists preserve their existing order, duplicates, insertion and removal behavior. Copies between blocks re-intern full records in the destination. No proof predicate uses a storage identifier. `IntStmtView` reads both shared lists and ordinary scratch vectors. Temporary generated rows remain ordinary `PagedVector` storage.

`logical_block/equality_propagation.hpp`, `cleanUpExpressions`, applies its precomputed removal decisions through `SharedExpressionList::eraseIf`: surviving identifiers compact in order without hashing or copying the full records and without changing their reference counts. Only removed positions release ownership. The local packed-key membership set is still rebuilt unconditionally when scheduled scopes have classes, including a pass that removes nothing, to purge stale keys from independent erasers. Original removed main-list positions still repair the per-class waterlines; delta history is emitted before removal.

Canonical deload tags 0 through 3 still stream the original full records in list order; reload rebuilds sharing. Raw eviction retains records, lookup buckets, reference counts and list identifiers as one arena image. Arena compaction changes only physical page bindings. The physical census counts `sharedExpressions` once and each list's reference pages separately. The canonical stream contains no new sharing metadata. See I-283.

## GPU request-frontier deload

GPU growth's pass-local frontier tails have a separate bounded disk path in
`gpu/request_frontier_store.hpp` / `RequestFrontierStore`. At most 32 MiB of row
payload per tail stays on the main pool; bounded page-directory, page-slack and
transfer storage are additional. Earlier rows live in two reusable positioned
files under `.deload/`. This does not make general worker scratch pageable and
does not enroll requests in `LbMemory::visitContainers`. The files and logical
contents live only within GPU execution; no proof artifact uses their offsets.
The existing deload permission and counterexample resident-only restriction apply.
See [the GPU cookbook](09d_gpu_cookbook.md#request-frontier-disk-storage) and
I-296.


## Independent GPU-host pool

`global_memory_manager.hpp` / `PoolKind::GpuHost`, `gpuHostMemory` and
`initGpuHostMemory` provide a fifth independent reservation. Its default ceiling
is `ProverParameters::static_gpu_host_pool_bytes` (4 GiB); `gpu_host_memory.hpp` /
`configuredGpuHostPoolBytes` accepts the separate `GL_GPU_HOST_BUDGET_MIB` override.
Blocks are 256 KiB and pages are 2 KiB. A pool-resident directory charges its own
rounded storage to that ceiling and handles both first-fit contiguous leases and
ordinary `LbArena` block grants. The four other pools retain their recycle order.

`GpuHostArena` suballocates stable aligned columns inside one exact lease. Used,
rounded reserved, committed and registered bytes remain distinct. Registration
accounting prevents release of a pinned range; the caller completes CUDA work and
unregisters before returning the lease. Returned blocks retain commitment for
reuse. This pool has no steward, pressure callback, logical-block deload registry
or extent file. GPU projections, retained name/rule data, fixed schedules, construction
scratch, chunk/task directories, window/shard/worker objects, device-pool host
metadata, request-frontier pages and sealing downloads use this reservation.
`ProjectionColumn` either owns a standalone lease or borrows aligned storage from
its enclosing arena. `GpuHostObjectArray` supplies pool-backed object lifetimes;
`GpuHostSpan` and `MemoryOrderView` borrow immutable contiguous directories.
The steward copies the order view at its existing synchronization boundary, so
the storage interface changes neither claim order nor eviction policy.

The streaming uploader borrows a live window's slot and empties it once the
upload and sealing copy finish; reuse waits for that release. Direct deferred upload registers one exclusive pool lease, and
frontier transfer scratch registers five exclusive blocks. Sealing download
columns reserve their fixed plan capacities on first download, after upload
windows have returned their leases. Shared processor/GPU executor infrastructure,
final `SealedPageSet` proof records, and operating-system/CUDA runtime internals
keep their existing ownership. CPU production batches create no GPU reservation.
Request-frontier disk spilling retains its existing permission and cache policy.

See I-299 and D-484.

## Returned pool commitment

`GlobalMemoryManager::trimRecycledBlocks` runs under each of the four original pools' mutexes at the phase-3 completion seam in `Prover::proveKernel`, before the barrier memory sample. It preserves the first 64 MiB of the existing returned-block queue per pool, decommits later committed entries, and never changes queue order, virtual addresses, granted blocks, logical grant counters or the steward's deload inputs. Adjacent addresses in queue order are released as one operating-system range. The queue and commitment flags live outside the released pages. `grantLocked` recommits a cold returned block before publishing the grant.

`address_space.cpp`, `decommitAddressSpace`, requires an exclusively owned whole-page range. Windows uses `MEM_DECOMMIT`; POSIX replaces exactly that already-reserved range with anonymous `PROT_NONE` pages. A later commit restores accessibility and zero-filled contents. Partial pages and operating-system failures assert; no failure fallback exists. This is a storage policy, independent of the census and enabled in ordinary runs.

`GlobalMemoryManager::commitment` records current and peak commitment, cumulative decommitted/recommitted bytes and trim calls. `memory_census::poolTouchedBytes` now sums current committed backing; its outside-pool residency subtraction remains an estimate. The report preserves the independent logical pool-purpose peaks and adds `[pool-commitment]` plus Windows lifetime page-fault counts. The GPU-host pool retains its committed backing and is excluded from trimming. Its commitment snapshot reports current equal to peak and zero decommit/recommit/trim totals. None of these counters select proof work. See I-297.

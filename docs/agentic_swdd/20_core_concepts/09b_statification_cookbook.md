# Core concept — Statification cookbook `[DRAFT]`

> You have a heap container in the main pipeline and you must make it static (Rule 28: heap → static, and statified code stays static — no new heap). This is the **type-indexed lookup** so you do not re-derive a pattern that already exists five times in the tree. Find your heap type in the table, copy the idea from the cited example, reuse the existing tool. Do **not** invent a new mechanism when a row already covers you (`feedback_no_overengineering`).
>
> The long-form *why* of the memory hierarchy lives in [`09_static_memory.md`](09_static_memory.md); the per-batch narratives + pitfalls live in the `I-pending-*` invariants ([`../30_invariants.md`](../30_invariants.md)). This file is the fast "I have an `X`, what do I use" crib.

## Definition — *statified* means 0% heap (read this first)

**A function is *statified* if and only if the CodeQL inventory (`statification/inventory.md`) marks its row `true`.** That is the objective, non-negotiable bar ([D-192](../40_decisions.md)). It means **0% heap**:

- No owning `std` container constructed as a local or temporary — `std::string`/`vector`/`set`/`map`/`unordered_*`/`deque`/`list`/`pair`/`tuple`, and no `to_string` / `.toStdString`.
- **No such type taken or returned BY VALUE.** A `const std::string&` or `StrSpan` parameter is fine — the *caller* owns those bytes — but a by-value `std::string` in or out is heap and fails the bar.

"Interior converted but the function still returns / takes a `std::string`" is **NOT** statified — that was the old, too-permissive bar and it is gone. Write genuinely heap-free code, never code that merely dodges the predicate (the CodeQL check has known blind spots for unnamed temporaries; exploiting them is a lie to the inventory — see `statification/codeql_temporary_detection_finding.md`).

**Where the heap goes — two rules that decide every conversion:**

1. **The boundary copy lives in the still-heap caller.** When a to-be-statified `A` had a heap interface and is called from a still-heap `B`: statified `A` takes spans/ids and writes into caller arena / out-params; `B` (not yet statified) does the `std::string`↔span copy. **Never leave the copy inside `A`.** This is the campaign's `…Scratch`-twin pattern — the twin *is* the statified form; migrating `B` onto it and removing `A`'s heap is the completion, not an optional follow-up.

2. **No static→heap→static walk-around.** If the caller already holds STATIC data (a `ScratchString` / `StrSpan` / arena value), it calls the statified function **directly, static→static**. Converting static→heap only to reach a heap function and converting the result back is **banned** — delete it, do not tolerate it. A `std::string` is materialized ONLY at a genuinely-heap sink not yet statified (`isAdmitted`, `addToHashMemory`, the compiled-definition layer) — and always in that heap caller/sink, never inside the statified function.

"Materialize at the edge" survives ONLY as rule 1's copy inside a not-yet-statified caller/sink. It is never a licence to keep a `std::string` inside the function you are calling statified.

## Step 0 — classify what you are converting

Two questions decide the whole approach. Get them right first.

1. **Transient (per-call scratch) or persistent (per-LB state)?**
 - **Transient** — created, used, and dropped inside one call (an accumulator, a substitution map, a decoded snapshot, a queue). → a **per-slot scratch arena** (`genScratchArenas` / `scratchArenas`), rewound/released per call. NO deload, NO tag. This is the common case and the whole subject of the transient-statification campaign.
 - **Persistent** — lives across calls on the LB, survives deload (the equivalence-class store, admission maps, origin maps). → a **cold deloadable container** on the LB's `LbArena`, enrolled in `LbMemory::visitContainers` with a `ContainerTag`. Bigger change; see [`09_static_memory.md`](09_static_memory.md) + I-95/I-123.

2. **Does the value cross a subsystem boundary you are not converting in this pass?** Then the boundary copy is the CALLER's job, not yours (see the Definition's rule 1). The function you are statifying returns a span/id (or writes into a caller out-param) — 0% heap; the still-heap consumer materializes the `std::string`/container it needs. If the caller already holds static data, it must NOT round-trip through heap to reach you (rule 2). "Convert the interior, keep the `std::string` boundary" does NOT count as converted — the inventory row stays `false` until the by-value heap leaves the signature too.

If transient: which scratch arena?
- **`genScratchArenas`** — the PAGE-tier container arena. Use for `PagedVector` / `ColdHashSet` / arena accumulators / `ArenaStack`. This is the default for anything container-shaped.
- **`scratchArenas`** — the byte-bump string-scratch arena. Use for `ScratchString` fill + per-call string windows. **Never** put a page container here (the `ScratchScope` rewind poisons the tail page — see pitfalls).
- Slot handle, everywhere: `const unsigned slot = (g_currentCoreId >= 0)? g_currentCoreId: <reserved high slot>; auto& a = genScratchArenas.forSlot(slot);` **Per-registry derivation:** the `-1` fallback comes from the `slotCount` of the registry BEING INDEXED — the two registries differ by one slot (`scratchArenas` has a dedicated reserved slot, `genScratchArenas` does not), so a slot derived from one must never index the other; a site touching both registries computes both slots (`G-57`).

## Tool reference

The reusable static substrate under `GL_Quick_VS/GL_Quick/src/memory_infra/`. Everything moves the working set off malloc onto ONE program-start reservation, addressed by virtual offsets/vids so images relocate and deload with zero pointer fixup. Layering: **pools** → **blocks** → an **`LbArena`** (byte-bump tier + page tier) → **containers** on one of those two tiers. "Static" = no `malloc`/`new`; a container owns only a few inline ints and resolves storage through its arena.

### The four process-wide pools (`global_memory_manager.hpp · GlobalMemoryManager`)

One class, four singletons selected by `PoolKind`. Grant order is nondeterministic under a mutex — sound only because no observable depends on physical block identity (I-107). Exhaustion is an `assert` naming the pool's config knob, never a fallback.

| Accessor | `PoolKind` | Config knob | Backs | Deloaded? |
|---|---|---|---|---|
| `staticMemory` | `Main` | `static_pool_bytes` | The deloadable per-LB main store; the scratch registries | Content round-trips to SSD |
| `persistentMemory` | `Persistent` | `static_persistent_pool_bytes` | Each LB's persistent `LbArena` behind `Memory::intToBeProved` | Never |
| `mailMemory` | `Mail` | `static_mail_pool_bytes` | Cross-LB pull-model mail (`mailArena` + `MailLog`) | Never |
| `lbMemory` | `Lb` | `static_lb_pool_bytes` | The `LbStore` object pool — `Memory` shells in `sizeof(Memory)` slots | Never |

`StaticMemoryConfig` = `{poolBytes, blockBytes, pageBytes, kind}`. Deload-ordinal assignment (`assignDeloadOrdinal` / `deloadRegistry`) lives here too (process documentation, Rule 16).

### Arena substrate (`lb_arena.hpp`, `scratch_arena.hpp`)

**`LbArena`** — the shared bump arena over pool blocks, addressed by `ArenaOffset` (`uint32_t` virtual offset; `kNullOffset` sentinel). One code path backs the per-LB store, the per-worker scratch arenas, and the sealed-page handoff — they differ in *lifetime*, not grant path. Two independent tiers on one arena:
- **byte-bump tier**: `alloc(bytes, align)` / `resolve(off)` / `cursor` / `popTo(off)`; scratch surface `mark` / `rewind` / `reset`. LIFO tail-free only.
- **page tier**: `allocPage→vid` / `freePage(vid)` / `pageAt(vid)` / `compactPages(scr)`. Pages addressed by stable vid so background compaction rebinds physical pages invisibly.

Lifecycle: `bind` / `releaseAll` / `markDeloaded` / `markResident` / `assertInvariants`. Persistent when a per-LB store; transient when a scratch/sealed arena.

**`ScratchArena`** = `using ScratchArena = LbArena` — same class, cold grant path, filled then wholesale-released per worker task. Transient; a resolved pointer stays valid until its `rewind` / `releaseAll`.

Two process-wide registries (both draw from `staticMemory`, one arena per worker slot = `coreId`, stable addresses via `std::deque`):
- **`scratchArenas`** — the string-scratch arenas (host `ScratchString`).
- **`genScratchArenas`** — a *second, distinct* per-slot set for phase-2 request generation; mixes byte-bump (`ArenaStack`) and page tier (append containers) so the string arena stays pure.

**`g_currentCoreId`** (`prover.hpp · Memory::g_currentCoreId`, `static thread_local int`) — the worker slot the current task runs on, or `-1` (→ reserved last slot) in single-threaded setup. Workers publish it on entry so the scratch helpers reach `forSlot(...)` without threading `coreId` through five signatures. The `-1` fallback is PER-REGISTRY (`<registry>.slotCount - 1` of the registry being indexed, never the other's — `G-57`).

## Pitfalls

Each of these cost a gate cycle in the campaign. Fix forward, never revert an incomplete arena rewrite (Rule 21) — a dirty tree during work is normal.

### Arena tiers & scratch fill

1. **`allocBytes` (page-tier scratch fill) must never share an arena with a live `allocPage` container.** A `ScratchScope` rewind on the byte tier freed and `0xCD`-poisoned the page-table tail a container was using → silent corruption (Gauss `collected` records clobbered, dropped statements failed to match, **theorems vanished with no crash**; membership-only `admittedVars` masked it because its bytes are never decoded as content). Now structurally eliminated: `LbArena::allocBytes` was retired to a resolved byte-bump `alloc` (`D-189`); the `genScratchArenas` move for `collected` is belt-and-suspenders. (`I-132`.)
2. **Page-tier and byte-bump tier are independent substrates — only `allocBytes`-vs-`allocPage` collided, NOT byte-bump-vs-page.** `alloc`/`cursor_`/`blocks_` and `allocPage`/`pageTable_`/`pageBlocks_` use separate block tables and distinct physical blocks, so `ArenaStack` (byte-bump) + `PagedVector` (page) coexist on one `genScratchArenas` arena freely. (`I-130`, `I-131`.)
3. **Two separate scratch arena families — never byte-bump the string arena, never page-vector the string arena.** Byte-bumping `scratchArenas` muddies the `ScratchString` liveness tripwire; a `PagedVector`/`ColdHashSet` on the string arena is freed by a `ScratchScope` rewind. `genScratchArenas` (containers + struct scratch) is deliberately distinct from `scratchArenas` (string views); both released per task at `performElem2` exit. (`I-124`.)

### Span / view lifetime

4. **Never `StrSpan(rawCharArray)` without an explicit length.** With no `const char*` ctor, `StrSpan(buf)` binds `StrSpan(const std::string&)`, builds a temporary, and the span dangles past the statement — masked the `collected` migration as a **Peano `isInt` divergence**. Always `StrSpan(buf, len)`. (`I-132` constraint 2.)
5. **`decodeView` spans / paged-metadata reads alias cold/page memory — COPY (or use owning `decode`) before any nested mint.** A nested mint (`encodePush`, `encodeExpression`, `nameMap.encode`) can grow a `PagedVector` onto a fresh page; a deload frees pages outright. A span taken before then dangles. `decode` now returns an owned `std::string`; the old `stackOf(id)` returning a heap ref is retired. (`I-3`, `feedback_namemap_copy`.)
6. **Blob-view reads snapshot; never hold an arena reference across a mutating call.** A later mutating call (e.g. `updateAdmissionMap` inside `isAdmitted`) can `assignRun` and invalidate the pointer. `admissionRecordsAt` returns an OWNED decoded copy (`I-99`); zero-copy blob views (`peekRecordBytes`, `EquivalenceClassView`, `OwnerSetBlob`, `AdmissionValueBlobView`) are valid ONLY while resident and until the run is next mutated — a recursive `emitNew → addStatement → self` needs a LOCAL page-straddle `clsScratch` so it cannot clobber the outer peek. **`isAdmitted` (S9 C4) is the second `AdmissionValueBlobView` consumer beyond the RMW insert:** because `updateAdmissionMap` mutates `admissionMap` inside its tuple loop, it copies every blob VERBATIM to the gen-scratch arena BEFORE the loop (`gArena.alloc` + `memcpy`, offsets re-resolved) and walks the copies — the `revisitRejected2` copy-before-mutate pattern (this pitfall's neighbourhood), the canonical-run order (I-99) making the blob walk byte-identical to the former `admissionRecordsAt` snapshot; per-tuple key/rem values are `ScratchString::copyFrom` snapshots on the string arena that survive the `valueInterner` mint. (`I-128`.) The packaged form `snapshotAdmissionRun(m, pk, gArena)` (`memory.hpp`) IS this copy-before-loop — verbatim blob copies + an arena `AdmissionValueBlobView[]`, `count == 0` a defined miss — and is what `updateAdmissionMapRecursion` (mutates `admissionMap` mid-loop via `insertAdmissionIdsBlob`, so the copy is MANDATORY) and `applyEquivalenceClassToAdmissionMap` (defers its erase/insert drain past the walk, so the copy is uniform not required) now call instead of `admissionRecordsAt` (retired from the `standardProcessing` tree, kept as the twin oracle — test `snapshot_admission_run_matches_admissionRecordsAt`). The rejected side has the two literal siblings `snapshotRejectedRun` / `snapshotRejectedIntegrationRun` (`RejectedValueBlobView` / `RejectedIntegrationValueBlobView` copies), byte-identical to `rejectedRecordsAt` / `rejectedIntegrationRecordsAt` on the canonical run (`I-148`; tests `snapshot_rejected_run_matches_set` / `snapshot_rejected_integration_run_matches_set`); `revisitRejectedIntegration2` and the two rejected equi-class hooks consume them the same copy-before-loop way.

### Interner ids & observable order

7. **Interner ids are first-seen (mint) order, NOT sorted — sort the DECODED key/string for every observable walk.** Id order equals allocation order, invisible only because everything is decoded before printing/comparing/sorting; comparing on raw ids is a determinism break. `exprKeyId` sorts on decoded `exprKey` (`I-97`); `SimpleMapStore::forEachChild` sorts by decoded routing-key `compareSpans` (`I-110`); `decodeOriginMapSorted` walks ids `1..count` then sorts by decoded `(expression, validity)` (`I-91`, `D-131`); every cold-map deload streams in id order but every observable walk sorts the decoded key (`I-84`).
8. **Observable order is the trap, not the container — a bulk key-mint must be pre-sorted.** The cold deload's canonical-bytes contract requires the byte stream be a pure function of logical content; a class-only key minted in unsorted iteration order deloads nondeterministically. The equi-class → body union in `updateEquivalenceClasses` processes class keys in SORTED order and rebuilds each key's run in place (`I-121`, `D-178`); `admissionMap` `appendRecord` breaks sort/dedup — always RMW through the decoded comparator (`I-99`).

### Deferred drains & single-threaded mint seams

9. **Deferred-drain-past-mint: while you hold `decodeView` spans over an interner's bytes, do NOT mint into that SAME interner.** The drain mints in NameMap (`resetResentExpressionRegistries`), relocating the pages the spans alias. Stage into a DIFFERENT arena interner and defer the NameMap-minting drain past the span-holding walk; the equi-class mail/admission hooks stage `MailRec` / `AmInsertRec` interned-id records on `genScratchArenas`, append in walk order, drain post-walk. (`I-128`.)
10. **Cross-LB writes from a parallel worker are forbidden — detect and defer to the post-join single-threaded drain.** Two workers concurrently minting a shared ancestor's cold `templateInterner`/`admissionMap` is a data race (`I-28`), surfacing as `cold-index desync` / `indexPlace: duplicate id`. `updateAdmissionMap3`'s ancestor climb seeded a shared fold ancestor inline — **deterministic cross-LB write every Gauss run, sporadic crash at Gauss hashburst 16**; fixed by staging on `deferredAncestorAdmissions` and replaying after `pool.join` sorted by a deterministic key (`D-187`).
11. **Never mint a process-global interner from a worker pool; pre-intern single-threaded before the pool spawns.** `skeletonInterner` / `mailInterner` are lock-free by design (read on the hot burst); a concurrent `mint` corrupts the cold key store + derived `PagedHashIndex` (`cold-index desync: minted key not findable at its id`). CE-filter workers each did `lb->setExprKey(std::to_string(i))`, minting `skeletonInterner` from up to 12 threads — fixed by pre-interning all CE `exprKey`s single-threaded (`D-186`, `I-97`, `I-83`). The routing `mailInterner` is FROZEN during the parallel phase; mints only at three single-threaded seams (`I-127`).

### Cold-container residency & lifecycle

12. **Cold-map `size`/`empty` reads as empty when deloaded — the residency assert is load-bearing, not defensive.** A deloaded container silently reads empty in RAM, so without the assert every loop over it no-ops while the LB's RAM-resident side tables stay mutable. Reloads run ONLY through `ensureLoaded` at enumerated touch points; a new assert hit means the touch-point list must grow, never the assert weakened. (`I-111`.)
13. **Every mail-inbox writer must `ensureArena` before its FIRST insert — never assume a prior insert bound it.** `RoutingColdMail` binds lazily; an origins-only committed blob (`stCount == 0`) runs zero `insertStatement`s, so the origins path writes through an UNBOUND arena — after mail statification `gl_quick.exe Peano` **AV'd (0xC0000005, no assert)** inside `Codec<Mail>::deserializeInto` (now the shared `deserializeMailBlobInto<Src>` body, whose `ensureArena` is its FIRST statement, before both loops); the incubator's first pulled blob always had a statement, masking it. (`G-55`.)
14. **Declaration order is load-bearing: a container must be declared AFTER its arena so it destructs first.** A container destructing after its arena `freePage`s on a dead arena. `persistentArena` before `intToBeProved` (`I-108`); `HashMemory` instances after `manager` in `LbMemory` (`I-123`); the `resetToFresh`-before-`releaseAll` order is the same trap (`D-149`).
15. **Cold containers outside the single `LbMemory::visitContainers` enumeration must be hand-threaded through EVERY arena-lifecycle op, or they corrupt.** `visitContainers` drives dump, load, release, AND discharge; a member declared outside `LbMemory` is missed by all four — three faces of one root cause: (1) release left `encodedMap` `PagedVector`s holding vids into a wiped arena → next reload `freePage`s garbage; (2) chapter export `ensureLoadedForRead`s every LB but nothing released them → pool exhaustion; (3) teardown destructs the four `HashMemory` after the arena. Retired only when `HashMemory` folded INTO `LbMemory` (`D-147`, `G-53`).
16. **Physical block identity / grant order must be invisible — store virtual offsets, never `char*`/`T*`.** A deload/reload may bind different physical blocks, and parallel grant order varies run-to-run; cold containers hold `ArenaOffset`, resolved per access, never sorted/hashed/dumped on pointer value (`I-107`). Steward deload-SET decisions read quiesced barrier counts + the monotone grant ledger only — never mid-iteration `blocksInUse`, which dips as async frees complete (`I-106`).

### No intermediate heap during conversion

17. **No intermediate heap `std::string`/`std::vector`/`std::set`/`IntInstruction` may cross a cold-store I/O boundary.** A transient built only to hand to an interner defeats the zero-per-burst-malloc goal. `ArenaIntegrationMap::buildFromCold` deserializes cold record bytes straight into arena `PagedVector`s via `peekRecordBytes`, and `writeToCold` serializes sorted arena entries straight into the blob run via the raw `assignRun` byte door (`I-133`); the absorb door interns from `StrSpan`s over stable input via additive `ValueInterner::encode(StrSpan)` / `mintOriginKey(StrSpan)` / `encodeExpression(StrSpan,…)` overloads (`I-129`).
18. **A cold mutation beyond append (`erase`/`setValueAt`) MUST escalate the aggregate to `Restructured` — else a tail-delta dump silently drops the change.** The canonical-bytes contract allows append-only tail deltas; an in-place write or compaction that stays `AppendedOnly` streams only the tail. `PagedVector::setAt`/`truncate` force `Restructured`; `erase`/`eraseIf` run one stable FORWARD compaction (survivor order preserved) + rebuild the index once (`I-119`, `I-118`). A back-swap remove would break cross-run byte-identity.

### Block-granularity sizing

19. **Every LB with any statified content pins at least one WHOLE block (default 256 KiB) — pool capacity is LB-count, not a byte budget.** The grant unit is a whole block; an LB holding one element still acquires a full block. Incubator batches run thousands of small LBs → `peakBlocksInUse ≈ live LB count` while deload files are tiny; the pool asserts far below the naive `pool_bytes / typical-LB-bytes` intuition. Fix by tuning `static_block_bytes` / `static_pool_bytes` in `parameters.hpp` — never add sub-block sharing without approval (breaks the one-owner-per-block lifecycle). (`G-52`.)
20. **Tier-1 deload frees only BETWEEN iterations — expecting "RAM proportional to thread count" is wrong.** `proveKernel` runs barriered sweeps and deload is the kernel's last act, so every LB active this iteration is resident from its phase-1 reload to end-of-kernel; the win is for LBs IDLE across iterations. The memory profile sawtooths per iteration. (`G-51`.)

## Verifying a conversion

- **Per function — the CodeQL inventory row is the objective gate.** A conversion is not done until `statification/inventory.md` shows the function `true` (or gone from the `standardProcessing` tree). That requires a full **Tier-1** regeneration (MSBuild `-t:Rebuild` under CodeQL trace → `database create` → `nodes.ql`/`edges.ql` → `make_inventory.py`); the Python-only Tier-2 re-reads stale CSVs and will NOT reflect a source change. Confirm the target flipped, no other row went `true→false`, and the rows before it stayed `true`. Never edit the inventory generator (`.scripts/call_tree_inventory/`) to move the bar — it is verifier-class.
- **Per commit — the differential unit test is the cheap byte-proof.** Every statified container ships a test asserting byte-identity or logical parity against the heap form it replaces, run via `gl_quick.exe --unit-tests`. The pattern is pervasive: `churned_container_dumps_canonical_bytes` / `double_dump_is_byte_identical` (`I-103`); `codec_idorigin_round_trip_and_byte_identity`; `merge_accum_serialize_matches_heap`, `arena_integration_map_matches_heap`, `clean_instruction_work_matches_heap`, `eqclass_raw_door_run_splice`. The "golden reference" heap-form `flatten`/`build` is deliberately KEPT as the test oracle even after the direct path replaces it in production. Per-commit gate is build-clean + `--unit-tests` green.
- **Batch gate — ONE full `main.py` + `verifier.py` + zero artifact diff + zero failures.** After a batch lands, the close-out is a single `main.py` run whose `theorems.txt` and ALL proof artifacts are BYTE-IDENTICAL to the pre-branch baseline (`git status files/` clean), the in-pipeline verifier reports 0 failures across every tag category, and the run completes with no pool-exhaustion assert (`D-151`, `D-152`, `D-186`, `D-187`). Byte-identity is the design contract ("byte-identity by construction"); the only exceptions are explicitly documented determinism reorders (`mailIn.exprOriginMap` order swaps in the intify batches — `D-131`/`D-133`/`D-135`). Multi-commit refactors build-only per intermediate commit and run the full gate ONCE after all commits land, bisecting on failure.
- **Determinism obligation — every cross-run / cross-host deviation is a bug, no exemptions.** The substrate is engineered so timing-dependent EXECUTION (async block frees, parallel grant order, which LBs deload when) never reaches a timing-dependent DECISION or a single output byte: offsets are a pure function of per-LB mutation history (`I-107`); deload files a pure function of logical content in id order (`I-103`); deload-SET decisions read quiesced barrier counts + the monotone grant ledger, never mid-iteration `blocksInUse` (`I-106`). The gitignored `.deload/` file SET may vary run-to-run precisely BECAUSE proof output cannot (`I-114`). Verification runs are sequential, never parallel. The strongest gate form is the two-sequential-`main.py` byte-identical check + verifier + theorem-presence (Gauss summation must be proved), sometimes run 3× (`D-185`, `D-187`).
- **Asserts are the tripwire and are LIVE in Release** (the project does not define `NDEBUG`): residency asserts, the `cold-index desync` round-trip check, and `LbArena::assertInvariants` (`GL_ARENA_PARANOID`) fire in production runs. A firing assert on a "can't happen" path is a gift that surfaces an unenumerated code path, never something to soften to recover a green run (Rule 19, `I-19`).

> **Agent-oriented documentation.** This document is written for AI agents working with the GL codebase. Human readers: see the [paper](https://arxiv.org/abs/2508.00017) and the [README](../../README.md). The document is intentionally dense, cross-linked, and weakness-explicit — agents thrive on that, humans usually don't.


# Optional browser checklist for proof HTML

This is a manual agent acceptance suite, not a substitute for browser interaction with a Python string test. The testing agent opens the generated proof book in a real browser, uses the mouse, observes screenshots and text, and records what actually happened.

## Use and evidence contract

This checklist is optional. `.scripts/html_browser_tests.py` (mandatory after every proof-HTML change, AGENTS.md *Proof HTML browser tests*) automates the cases a script can decide; `--list` shows which. The remaining cases, and the judgment parts of automated ones, are a look at the saved screenshots. AGENTS.md (*Proof HTML browser check*) requires the coding agent to check its own HTML changes in a real browser; running these cases with several agents needs the maintainer's approval (AGENTS.md Rule 37). The cases catalogue what is worth looking at after a change affecting generated proof HTML, including generation code, notation code, styles, scripts, tag descriptions, link routing, proof placement or reader block logic. Prepare a review request with `.scripts/html_browser_review.py prepare --html <book> --output <request.json>`. It selects the longest and shortest proofs from the rendered row metadata, pins source and page hashes, and lists every case below as pending. Never reuse a browser sign-off after a source or selected-page hash changes.

The testing agent records one result per case in the request: `pass`, `fail`, or `not_applicable`, with observed behavior and evidence paths. `not_applicable` requires an artifact-based reason that the selected full book has no such case, not a lack of time or inability to open the browser. A browser access failure is `blocked`, never pass. The final `check` command rejects pending, failed, blocked, duplicate, missing or stale results. It does not pretend to verify pixels: the named agent is accountable for the observations.

Select additional real chapters for integration containing a subproof, disintegration from a premise and from a derived fact, an integration result that closes a goal, a disintegration result that closes a goal, OR introduction and elimination, deepest scope hierarchy, induction, contradiction and the longest multiline implication. Record chapter URLs before the first action. If the longest expanded proof differs from the proof with most closed main rows, test both. Use actual artifact coverage to choose examples rather than guessing chapter numbers.

For each case: observe first, perform the listed action, observe again, compare with the expected result. Save screenshots for default view, common-only view, the deepest opened hierarchy, both closed goal-result jumps, the longest implication, narrow viewport and zoom. A changed visual baseline needs an explanation. Do not mark all cases passed from one screenshot or infer click behavior from source code. Fix failures, regenerate, refresh hashes, and rerun affected cases plus the default/longest-proof smoke cases.

## Completion

Record source commit, source hashes, generated-book path, browser, viewport, zoom, testing agent identity, chosen chapters and evidence directory. Summarize failures and fixes in the task ledger; raw screenshots and interaction logs belong under `.debug/`. Run `.scripts/html_browser_review.py check --request <request.json>` before accepting the HTML milestone. A green formal verifier or Lean certificate does not constitute a browser pass, and a browser pass does not constitute a formal proof certificate.
